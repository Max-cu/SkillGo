# 持久化任务快照（第一阶段）

## 已实现

通过 `SKILLGO_DURABLE_CHECKPOINTS_ENABLED=true` 启用。compose 将开关传给 API 和任务 Worker；无需数据库迁移。

每个模型轮次开始前，在上一工具轮次完成后冻结工作区，保存：

- `/workspace` 普通文件、目录、权限及文件 SHA-256。
- Agent 消息、计划、验证证据、计数、执行位置和固定脚本状态。
- Skill 版本、模型名称、网络权限和当前镜像 ID。

快照位于共享 storage 的 `checkpoints/<user>/<job>/<uuid>.zip`。采用 JSON 和无压缩 ZIP，不使用 pickle；文件原子发布并 fsync 后，在租约校验下更新数据库指针。快照使用由 JWT secret 派生的 HMAC 校验身份与完整性，不提供额外静态加密。密钥轮换后旧快照不能恢复。

工具调用前先把快照标记为 `in_flight`。Worker 租约过期后：

- `ready`：新 Worker 在相同镜像中恢复文件和 Agent 状态，继续下一轮。
- `in_flight`：返回 `CHECKPOINT_TOOL_UNCERTAIN`，保留快照，禁止自动重放可能已经产生副作用的操作。
- 校验失败或文件丢失：明确失败，不静默退回原始输入重跑。

正常完成时解除快照引用，由孤儿清理回收；失败保留至任务存储保留期结束；删除任务同时删除快照。活动任务的快照不会被孤儿扫描误删。正常等待用户回复仍沿用现有回答后重启语义，解除旧快照引用，避免旧上下文覆盖新回答。

## 限制与上线门槛

这是文件和 Agent 状态恢复，不是 CRIU 进程快照。进程、内存、后台作业、`/tmp` 不恢复。直接固定入口任务尚未纳入。Worker 等待环境构建时仍占一个任务执行槽。

第一版每轮全量复制，工作区最多 256 MiB / 10000 条目，Agent 状态最多 16 MiB；大文件任务会增加磁盘和冻结耗时，不应未经性能验证直接全量启用。每任务保留一个当前引用；原子替换期间和孤儿清理前可能有多个对象。尚无全局快照容量配额。

本地验证包括：身份/篡改拒绝、持久化序列化、提交结果不确定时保留对象、全 Agent 循环丢弃原状态后恢复、租约回收边界、活动引用及过期回收。沙箱使用测试替身。

上线前应在独立测试任务/隔离数据库中用真实 Docker/gVisor 执行进程退出与重新启动演练，验证文件校验、镜像固定、工具不重复及资源回收，并记录大工作区每轮耗时。完成该演练前保持默认关闭，不影响生产任务。

生产启用方式：在 `deploy/ecs.env` 持久设置 `SKILLGO_DURABLE_CHECKPOINTS_ENABLED=true`，任务空闲时重建 API 与任务 Worker，检查进程配置和网页健康。回退开关为 false 会停止新任务生成快照；已有持久化快照仍可恢复。

增量镜像部署必须保留非 root 用户对 Python 包目录的访问权限（目录 755、文件 644，属主 10001）。停服前用候选镜像导入 `app.main` 与 `app.sandbox_worker`；之前权限错误已自动回滚并修复。
