# Skill 专用运行环境

新版本可启用 minimal-v1，已有版本继续使用原绑定镜像。

## 准备与复用

1. 使用 sandbox-runtime/Dockerfile.minimal 构建公共底座，取得不可变镜像 ID。
2. 在 API、任务 Worker、环境准备 Worker 中配置 SKILLGO_ENVIRONMENT_MINIMAL_BASE_IMAGE。
3. 上传新版本后，平台根据能力声明、源码导入和 Python 依赖生成清单。
4. 清单包含底座 ID、布局版本、系统组件和能力默认依赖。依赖解析结果、精确版本和哈希保存于环境库存。
5. 相同清单共享缓存环境，已准备的镜像用于后续任务。

环境准备 Worker 按 SHA-256 缓存公开 wheel 文件。每次读取都会校验哈希，重试或构建其他清单时只下载缺失的文件。安装仍按各自的锁定清单离线进行，缓存卷只挂载到环境准备 Worker。缓存超过 4 GiB 时优先清除最近最少使用的 wheel。

Python 包安装到镜像内的 /opt/skillgo/python。平台控制的 site hook 使常规 Python 和 python -I 优先加载该目录。基础镜像的软件包保持原样，第三方 wheel 自带的 .pth 文件不在此目录执行。

系统组件按能力准备，例如 fonts.cjk 安装字体，office.convert 安装 LibreOffice。Skill 自定义的系统安装脚本不会进入这一构建步骤。

## 运行核验

环境构建阶段做完整功能探测。任务启动阶段只探测该任务所需的提供者，日志区分本次所需能力与环境库存。运行时补充依赖会从原清单重建并合并新增要求。

## 删除与保护

删除 Skill 时标记其环境供构建服务回收，无保留期。其他版本共用的环境、运行任务引用的环境、仍有沙箱使用的镜像会保留。无引用的专属镜像使用非强制删除；公共底座和其他环境共享的镜像继续保留。构建服务繁忙时，回收会在其下一次空闲循环执行。

已有运行任务沿用原镜像。已有准备失败的版本可通过重试入口重新生成清单，无需重新上传。
