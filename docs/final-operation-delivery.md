# 通用最终操作交付

本功能是平台执行协议，不需要修改上传的 Skill 包，也不依赖账号、Skill 名称、版本 UUID 或文件扩展名。适用于启用了文件接收模式的任务；完整验证模式保持原有验证及结束路径。

## 工作方式

模型在最后一次 `command`、`run_python`、`write_file`、`write_json`、`run_commands` 或 `run_skill_workflow` 调用中，可同时声明：

```json
{
  "delivery": {
    "summary": "已完成报告，并通过 Skill 要求的检查。",
    "artifacts": ["/workspace/skills/report/exports/result.csv"]
  }
}
```

这是工具参数的一部分，不是让 Skill 脚本输出特殊标记。模型必须将生成/导出、所有剩余的 Skill 检查和清理安排在这次调用中，且本轮只能有这一个工具调用。需要先查看运行结果再决定的步骤不能硬塞进最终命令组。

平台在执行前后对声明的精确路径流式计算大小和 SHA256。只有下列条件均成立，才自动收集文件并通过既有 Worker 持久化路径结束任务，无需下一轮 `finish`：

1. 整组操作成功，没有失败、超时或被跳过的命令。
2. 全部声明文件非空，且相对于执行前是新文件或字节已变化。
3. 路径位于任务工作区，没有通配符、重复路径、目录或符号链接穿越。
4. 收集时文件字节与本组执行后的指纹一致。
5. 原有计划和 Skill 完成门槛满足，且任务未取消。

本机制以模型在操作前明确声明完成意图为前提，不推断任意命令或目录的业务含义。它不会证明内容或版式质量，也不会替代 Skill 自带检查和模型需要执行的看版工作。

## 回退与兼容

- 最后操作失败时保留成功部分，由模型处理报错，不收集为成功结果。
- 旧文件未变化、路径未知、指纹不可读取或收集不一致时，返回诊断，继续普通执行和 `finish`。
- 如果文件已在上一组操作完成，或本组覆盖后字节完全相同，使用普通结束路径，不要为了触发自动交付重新导出。
- 多 Skill 任务仍须满足全部 Skill 的完成条件；此字段不能绕过它们。
- 原有指定版本工作流交付适配仍保留，互不降低证据要求。

记录 `operation_auto_delivery` 事件。只有现有文件保存流程成功后，任务才能被标记为成功。不开启额外摘要模型调用；不扫描目录猜测最终产物。

## 部署与发布

通用路径随文件接收模式生效。`SKILLGO_ARTIFACT_DELIVERY_ONLY=true` 使其对整个实例可用；按 Skill 白名单的接收策略也仍可使用。不增加数据库迁移或新的版本白名单。

这是 v1.0.0 之后的改动，源码和文档以对应提交为准，不会修改已发布标签。部署新 API 和 Worker 代码后，新任务提示词才会引导模型使用该协议。既有运行任务不得因启用而被中断。
