# 同环境沙箱切换：第一阶段

接口：`POST /api/v1/jobs/{job_id}/sandbox/restart`。仅任务所有者可请求，任务必须是正在运行的 Agent 沙箱任务。请求幂等，每个任务最多三次；固定入口任务不支持。

Worker 在完整工具轮之间处理请求，保留内存中的 messages、AgentExecutionState、操作编号、计划和验证证据。冻结旧容器，经只读卷导出文件到有界内存快照，拒绝链接、特殊文件和路径越界。限制 256 MiB 文件内容及 10,000 个条目。

新沙箱绑定旧容器的不可变镜像 ID，保持网络权限。恢复普通文件、目录、权限，并逐文件校验 SHA-256，成功才替换容器并清理旧卷。失败清理候选并解冻原容器；任务取消在切换前检查。事件保存下一轮编号、完成操作数、镜像 ID、文件数、字节数与校验清单摘要，不保存文件内容。

这不是持久化崩溃恢复。Worker 必须存活，快照暂存在 Worker 内存；Python 内存、后台进程、/tmp 不恢复。失败后可以重新发起请求。暂未提供 UI 按钮，也未接入 request_capability。生产上线前需要正常发布流程。

验证：单元测试覆盖安全路径、链接拒绝、大小限制、复制/校验失败回退、取消、请求鉴权与幂等、下一轮继续。服务器独立合成文件实测验证了新容器 ID、原文件、空目录、执行权限以及切换后继续写入；未使用用户文件。

后续：持久化加密/访问隔离快照与 Worker 租约恢复协议、资源配额与保留期，再接环境升级。不能将当前内存快照当作 Worker 崩溃后可恢复的备份。
