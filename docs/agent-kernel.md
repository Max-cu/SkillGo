# SkillGo Agent 内核

SkillGo 使用“模型负责理解和决策、Worker 负责可信状态、一次性沙箱负责执行”的三层结构。模型不能直接访问宿主机、数据库、其他用户文件或模型密钥。

## 当前执行路径

1. API 固化用户消息、附件、Skill 版本和运行模型，任务进入队列。
2. Worker 为任务创建独立工作区和 gVisor 容器，挂载输入与已审核 Skill。
3. Agent 完整理解用户要求和相关 `SKILL.md`，建立 2–8 步的简短执行计划，其中明确一个最终验证步骤。
4. Agent 通过结构化工具完成读取、处理和产物生成；多 Skill 按用户指定顺序依次加载和协作。
5. 产物生成后只做一次集中验证：优先运行 Skill 自带验证器，否则依据本次用户要求和 `SKILL.md` 生成一个紧凑验证程序。
6. 验证失败时只修正被证实的问题，最多允许两轮定向修正；仍不通过则如实失败，禁止空转。
7. Worker 校验真实文件路径、哈希及 DOCX/XLSX/PPTX/PDF/JSON 的基本结构后保存产物。
8. 容器与临时依赖随任务销毁，产物回到用户自己的持久工作区。

## 执行质量策略

- 原始要求优先：完整用户要求和 `SKILL.md` 是唯一任务标准，不再生成可能丢信息的中间“验收合同”。
- 简短计划：用少量完整阶段管理执行，不把每个细节拆成一次模型轮次。
- 集中验证：一次验证同时覆盖本次 Skill 承诺的关键内容、呈现和交付物，并输出段落数、字体、测试数、来源数等真实观测值，而不是只输出 `PASS`。
- 验证时效：写文件或再次执行转换会使旧验证自动失效，必须验证最新产物。
- 定向修正：验证失败只修复已发现的具体问题，不重新执行无关流程；最多两轮。
- 无额外模型审查：不增加验收合同编译、合同审计和第二个模型复审，减少延迟、费用和误判。
- 多 Skill：初始只提供名称、摘要和根目录，到对应阶段再用 `read_skill` 加载完整说明，降低上下文干扰。
- 长上下文：近期工具结果保留全文；超长结果写入 `/workspace/work/tool-results`，旧消息保留摘要和恢复路径。
- 防循环：忽略展示性参数生成语义指纹；工作区未变化时复用重复读取；等价动作反复出现会中止空转。
- 基础完整性：平台继续拒绝空文件、伪 DOCX/XLSX/PPTX、损坏 PDF 和无效 JSON；领域质量由 Skill 的集中验证负责。

这套设计不硬编码“必须语义分段”或“必须使用某个字体”。文档 Skill 可以验证排版，代码 Skill 可以验证测试，检索 Skill 可以验证来源，新的 Skill 类型无需修改平台内核。

## 网络与依赖

- 没有网络声明的 Skill 保持离线。
- 声明网络、在线查询或依赖下载的 Skill，任务沙箱可获得出站网络。
- `pip`/`npm` 依赖安装到任务工作区，仅当前任务可见并随沙箱销毁。
- `apt`/`apk` 等系统级安装继续禁止，不能修改宿主机。

当前网络控制粒度是“按任务开关”。域名白名单、代理审计、依赖锁文件校验与缓存仓库属于下一阶段安全增强。

## 评估指标

每次 Agent 内核调整至少观察：任务成功率、产物格式有效率、平均推理轮数、工具调用数、重复调用率、验证失败后的修正次数、耗时与模型 token。不能只以“能跑完一次”判断优化是否有效。
