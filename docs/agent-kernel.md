# SkillGo Agent 内核

SkillGo 使用“模型负责理解和决策、Worker 负责可信状态、一次性沙箱负责执行”的三层结构。任务级独立环境首先解决多用户文件、依赖、进程和运行状态互不冲突；gVisor 在此基础上提供纵深隔离。模型不能直接访问宿主机、数据库、其他用户文件或模型密钥。

## 内核模块边界

- `sandbox_worker.py`：数据库租约、任务尝试、沙箱生命周期、结果持久化和尝试级重跑。
- `sandbox_agent_loop.py`：模型工具循环、上下文裁剪、进度事件和受限工具调度。
- `sandbox_tool_registry.py`：工具名称、参数校验和工具能力分类。
- `agent_policy.py`：计划、Skill 顺序、验证状态、重复动作和完成条件。
- `agent_context.py`：按模型预算投影上下文，固定保留原始要求、活动 Skill 和可信检查点。
- `workflow_tools.py`：执行验证器、文件哈希、已确认答案和步骤输入输出绑定。
- `agent_tool_specs.py`：扩展工具协议；`model_adapter.py`：推理参数、请求预算与传输重试。
- `artifact_validation.py`：产物路径、结构校验和 SHA-256 快照。
- `deterministic_runtime.py`：固定入口 Skill 的无模型选择执行路径。
- `sandbox_runtime.py`：Docker Volume、gVisor 容器、命令和文件传输。

## 当前执行路径

1. API 固化用户消息、附件、Skill 版本和运行模型，任务进入队列。
2. Worker 为任务创建独立工作区和 gVisor 容器，挂载输入与已审核 Skill。
3. Agent 完整理解用户要求和相关 `SKILL.md`，建立 2–8 步的简短执行计划，其中明确一个最终验证步骤。
4. Agent 通过结构化工具完成读取、处理和产物生成；用户指定的 Skill 保持原顺序，自动选择的 Skill 根据步骤依赖协作。每个阶段声明 `depends_on`、`input_refs`、`output_refs` 和所属 `skill_index`；依赖未完成或实际输入不存在时不能开始，输出不存在时不能完成。已完成阶段的输入或输出变化会使该阶段及其下游失效。
5. 产物生成后执行集中验证：通过专门的 `run_verifier` 运行 Skill 自带检查或依据本次要求编写的程序。平台绑定命令退出码、结构化检查结果、验证程序文件哈希和验证前后全部输出文件的 SHA-256，生成唯一 `verification_id`。普通命令成功不能充当验证通过证据。
6. 验证失败时只修正被证实的问题，最多允许两轮定向修正；仍不通过则如实失败，禁止空转。
7. `finish` 前重新计算全部产物 SHA-256；字节与验证快照不一致、存在未声明文件或缺少验证证据时拒绝完成。Worker 随后校验真实文件路径及 DOCX/XLSX/PPTX/PDF/JSON 的基本结构并保存产物。
8. 容器与临时依赖随任务销毁，产物回到用户自己的持久工作区。

## 执行质量策略

- 原始要求优先：完整用户要求和 `SKILL.md` 是唯一任务标准，不再生成可能丢信息的中间“验收合同”。
- 简短计划：用少量完整阶段管理执行，不把每个细节拆成一次模型轮次。
- 集中验证：一次验证同时覆盖本次 Skill 承诺的关键内容、呈现和交付物，并输出段落数、字体、测试数、来源数等真实观测值，而不是只输出 `PASS`。
- 验证时效：写文件或再次执行转换会使旧验证自动失效，必须验证最新产物。
- 定向修正：验证失败只修复已发现的具体问题，不重新执行无关流程；最多两轮。
- 无额外模型审查：不增加验收合同编译、合同审计和第二个模型复审，减少延迟、费用和误判。
- 多 Skill：初始只提供名称、摘要和根目录，到对应阶段再用 `read_skill` 加载完整说明，降低上下文干扰。
- 长上下文：按模型输入预算保留原始请求、完整活动 Skill、已完成阶段证据和完整近期工具往返。超长结果写入 `/workspace/work/tool-results` 后返回合法 JSON 摘录与读取路径；不截断 JSON、不改写原生工具参数或推理字段。预算采用保守 UTF-8 估算，不等同于各供应商精确 tokenizer；原始要求本身超预算时明确报错。
- 防循环：忽略展示性参数生成语义指纹；工作区未变化时复用重复读取；等价动作反复出现会中止空转。
- 基础完整性：平台继续拒绝空文件、伪 DOCX/XLSX/PPTX、损坏 PDF 和无效 JSON；领域质量由 Skill 的集中验证负责。

这套设计不硬编码“必须语义分段”或“必须使用某个字体”。文档 Skill 可以验证排版，代码 Skill 可以验证测试，检索 Skill 可以验证来源，新的 Skill 类型无需修改平台内核。

## 固定入口模式

带 `skillgo.yaml` 的单 Skill 可以声明不可变 argv，由平台直接执行，不让模型选择脚本：

```yaml
spec:
  type: code
  execution:
    mode: fixed
    entrypoint: [python3, scripts/run.py]
    verifier: [python3, scripts/verify.py] # 可选；必须只读最终产物
    timeoutSeconds: 300
    verifierTimeoutSeconds: 120
```

固定入口从 `/workspace/work/skillgo-job.json` 读取任务说明（含用户已确认答案）和输入文件索引，将最终文件写入 `/workspace/output`。平台先运行 `entrypoint`，再运行可选 `verifier`；verifier 修改产物字节会使任务失败。单固定 Skill 保持无需模型选择的执行路径。多 Skill 使用 Agent 编排，其中固定阶段必须调用 `run_fixed_skill` 执行声明的不可变入口；此前产物加入输入索引。禁止模型用自行编写的计算替代该入口。混合任务仍须完成任务级集中验证。

## 验证协议与视觉检查

计划中的成功标准按顺序编号 `r1`、`r2` 等，重规划不得删除或替换已有标准。`run_verifier` 的 stdout 必须是一个 JSON 对象，例如：

```json
{"checks":[{"requirement_id":"r1","passed":true,"observed":{"expected":42,"actual":42}}]}
```

允许 1–200 项检查，每个标准至少有一项观测。退出码非零、任一检查失败、缺少标准、损坏产物或验证过程修改输出字节，均不能登记为通过。`record_validation` 必须引用最新真实 `verification_id`；模型填写的文字说明不能覆盖失败结果。完整报告存于沙箱 work 目录，精简证据保存在任务 memory，可由任务所有者通过 `GET /api/v1/jobs/{id}/verification` 查询；输出变化后报告标记为过期。

Agent 可通过 `inspect_image` 检查沙箱中生成的 PNG/JPEG/WebP，返回绑定图片 SHA-256 的视觉观测。文档须先利用可用渲染工具生成页面图片。该能力需要配置默认视觉模型；不可用时会返回明确工具错误。视觉判断帮助发现排版问题，不自动代替验证器或业务验收。

这里保证的是检查确实执行且绑定实际文件；检查程序仍可能遗漏业务要求，或判断标准本身不充分。原始请求始终保留，但平台不声称已形式化证明全部用户意图。

## 自动选择与澄清

工作台可开启“自动选择 Skill”，API 对应 `POST /api/v1/jobs` 的 `automatic=true`。手动插入 Skill 时仍以手动选择为准。候选范围仅包含当前用户有权运行的可用版本，先按任务相关性排序，再将最多 40 个候选交给模型选择 0–5 个。单候选也允许判断不匹配，零相关性回退不强行选择；没有匹配时返回可解释错误。当前召回是词项排序，语义召回质量留给业务测评检验。

缺少关键单位、范围或其他必要信息时，Agent 可单独调用 `ask_user`，任务进入 `waiting_user` 并释放沙箱与租约。工作台和任务详情显示提问；所有者通过 `POST /api/v1/jobs/{id}/answer` 提交问题 ID 和答案，平台复核任务状态、输入保留期与 Skill 权限后恢复排队。同一问题重复提交返回冲突。最多保留 10 次回答；人工等待不消耗 Worker 故障恢复次数。

恢复使用新沙箱，从原始附件及全部确认答案重新执行，不恢复半成品文件。失败后创建重试任务同样继承答案和已保存对话上下文，但重新计算执行尝试预算。任务创建时保存本对话近期文本背景；用户本次完整要求优先于背景。

## 模型适配

平台设置中可配置兼容协议或推理模型协议、推理强度、上下文总预算和最大输出预算。兼容协议使用 `max_tokens`，推理协议使用 `max_completion_tokens`；配置推理强度时不同时发送温度。应按所选供应商实际支持的参数填写，不会擅自切换用户选定的模型。

原生工具明确不受支持时才缓存兼容模式，不把所有 HTTP 400 误判为不支持工具。推理请求遇到 429、502、503、504 或指定连接/读取错误时，在总超时内最多尝试三次；已经执行的工具不因模型传输重试而重放。新字段由 `20260907_0007` 数据库迁移添加，历史配置保持兼容默认值。

## 中断与重跑语义

沙箱隔离粒度是“一次执行尝试”，不是可恢复的长期环境。Worker 租约过期后，旧容器和 Volume 会被回收；下一次尝试使用新的 `execution_id`，从固定 Skill 版本和原始输入重新开始，不恢复半成品工作区。运行事件明确记录 `restart_policy=fresh_attempt` 和 `workspace_restored=false`。这保持环境干净且避免继承不一致的中间状态；阶段快照只在长任务成为主要场景后再评估。

## 网络与依赖

- 所有 Skill 版本默认保持离线；内容分析只提示潜在联网需求，不能自动授予权限。
- 管理员可以在审核时或发布后为具体 Skill 版本开启、关闭“运行联网”。
- 多 Skill 任务中只要一个选中版本获得联网授权，整个一次性任务沙箱即联网；任务记录会保存授权来源快照。
- `pip`/`npm` 依赖安装到任务工作区，仅当前任务可见并随沙箱销毁。
- `apt`/`apk` 等系统级安装继续禁止，不能修改宿主机。
- `SKILL.md` 示例提到的命令作为依赖提示；只有显式元数据和固定入口/验证器声明的命令进入启动前硬依赖检查，避免把可选示例误判为必需环境。

当前联网使用普通 Docker bridge，不限制目标域名，也不提供出口代理或 SSRF 拦截；因此只应为管理员已经审核并信任的 Skill 版本开启。域名白名单、代理审计、依赖锁文件校验与缓存仓库属于下一阶段安全增强。

## 评估指标

每次 Agent 内核调整至少观察：任务成功率、产物格式有效率、平均推理轮数、工具调用数、重复调用率、验证失败后的修正次数、耗时与模型 token。不能只以“能跑完一次”判断优化是否有效。
