# 编排恢复与加速验收

框架只在相同读取窗口返回相同内容、且完整结果仍在本轮模型上下文中时判定重复。
分页、补读被投影掉的结果和文件改变后的读取均保持有效。脚本可能改写 Skill 的
`assets`、`exports` 等目录，因此执行命令后保守失效普通读取缓存；不可变参考书架单独保留。
没有引入历史交互数量上限、参考正文裁剪或 checkpoint 降频。

重复读取错误走普通工具收尾：批次在首个错误停止，返回已执行结果和跳过索引，
一个父调用只有一个回复。指导信息在全部待处理回复之后发送。普通脚本和 verifier
失败的简短诊断保留在执行状态中，匹配操作成功后清除；它们不会替代完整输出与原有验收。

后端事件新增 `cache_hit`、`cache_type`、`read_offset`、`read_limit`、`returned_chars`、
`total_chars`、`complete`、`eof`、`observation_repeats`，重复失败还记录
`failure_signature`、`repeated_failure_count`。这些字段不保存文件正文。

固定回归覆盖普通分页、自动完整读取、Skill 目录的脚本改写、父目录列表失效、
缓存容量、旧快照、被上下文投影移除的正文、批次首次失败停止、原生工具消息配对、
恢复后验证交付，以及非零退出的部分修复后重验。

真实性能对照应使用完全相同的指令、附件哈希、Skill 版本、模型及模型选项，
每组至少运行三次，同时测试需要文件处理和纯文本工具的其他 Skill。报告成功率、
产物检查结果、总耗时中位数、模型轮次、模型耗时、工具耗时、重复错误数与缓存命中。
`input_estimated_tokens` / `context_budget` 是估算值，应与模型返回的实际 token usage 分开。
因错误提早终止、减少必要检查或降低交付质量，均不算加速。
