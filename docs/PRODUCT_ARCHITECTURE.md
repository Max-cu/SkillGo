# SkillGo 产品与技术架构（Agent × SkillHub × 独立沙箱）

## 1. 产品定义

SkillGo 不是“给每个 Skill 做一个运行表单”，而是一个以对话为入口的多用户 Agent 平台：

- 用户用自然语言和文件描述目标。
- Agent 从已安装或有权访问的 Skill 中选择能力。
- Skill 提供可复用的说明、脚本、资源、权限和验收规则。
- 复杂任务在用户独立的受控沙箱中执行，并产生真实文件和可追溯记录。
- Skill 可以在社区中发布、安装、升级、派生和复用。
- 同一套完整流程可以通过网页、API、异步任务和 Webhook 调用。

一句话定位：**Conversation-first、Skill-native、Sandbox-per-user 的 Agent 与 SkillHub 平台。**

## 2. 核心设计原则

SkillGo 采用以下通用 Agent 工程原则，并围绕多租户平台独立实现：

1. 对话是主界面，Skill 是 Agent 的能力，不是孤立的页面。
2. 系统提示只暴露 Skill 的名称、描述和位置；确定要使用后才读取完整 `SKILL.md`，避免一次塞入全部说明。
3. 一次模型推理可以返回多个工具调用，不把每个文件动作都变成一次新的模型往返。
4. 工具失败以结构化结果返回给 Agent，让它有界重试，不因普通路径错误直接终止任务。
5. 长上下文采用“近期原文 + 历史摘要 + 文件状态”，旧工具输出可裁剪，完整内容留在工作区文件中。
6. 长任务具有独立的任务状态，不依赖模型记住“做到哪一步”。

同时明确以下产品边界：

- 面向个人电脑的单工作区方案不适用于多租户平台；SkillGo 必须增加用户、组织、数据库、对象存储、密钥和沙箱边界。
- 不能让不同用户共享同一个工作目录、浏览器状态、环境变量或工具凭据。
- 不能只靠提示词限制权限；权限必须由平台和沙箱强制执行。

## 3. 目标体验

### 主工作区

- 左栏：新任务、会话、我的 Skill、任务、文件、API；管理员能力按角色显示。
- 中间：自然语言对话、附件、流式回复、任务卡片和产物卡片。
- 右侧检查器（默认收起）：本轮使用的 Skill、沙箱状态、文件、任务步骤、权限审批。
- “运行工作流”页面保留为任务详情/调试入口，不再是普通用户的首要入口。

### 用户心智

用户只需要说“审查这个文档并生成修改稿”。平台负责：

1. 识别任务和候选 Skill。
2. 必要时让用户确认能力或高风险权限。
3. 创建带独立工作区的任务。
4. 持续执行到完成、失败或确实需要信息。
5. 在对话中返回摘要和可下载产物。

## 4. Agent 执行分层

### 4.1 路由层

一次轻量模型调用决定：

- 直接回答；
- 使用某个或多个 Skill；
- 启动确定性工作流；
- 启动探索型 Agent；
- 转为后台任务；
- 请求用户批准高风险操作。

模型只看到可访问 Skill 的目录摘要。完整 `SKILL.md` 在选中后按需加载。

### 4.2 混合执行层

优先级从高到低：

1. Skill 自带的确定性入口脚本或声明式 DAG；
2. 平台级文档、表格、文件工具；
3. 少量 ReAct 推理解决不确定决策；
4. 不允许模型用几十个微小写入手工模拟本可由一个脚本完成的工作。

一次推理允许返回多个工具调用。读目录、读取互不依赖的文件可以批量；写入和命令按返回顺序执行。`finish` 必须单独调用并验证真实产物。

平台分别记录：

- `reasoning_turn_count`：模型推理轮数；
- `tool_operation_count`：真实工具操作数；
- `logical_phase`：展示给用户的业务阶段。

用户界面默认只展示业务阶段，底层工具调用放在“执行详情”中。

### 4.3 上下文层

会话上下文由四部分组成：

- 最近若干轮原始对话；
- 自动维护的历史摘要；
- 当前任务/计划状态；
- 工作区文件索引和必要片段。

旧工具输出只保留短摘要和文件引用，完整数据落到用户工作区。会话数据库与沙箱文件状态分别持久化，但都带 `tenant_id/user_id/conversation_id` 边界。

## 5. 独立沙箱模型

当前 2 核 4G 服务器不适合为每个会话永久保留容器。第一阶段采用：

- **每次任务/Agent 回合创建临时 gVisor 沙箱**；
- **每个会话拥有独立的持久工作区快照**；
- 回合开始时将该用户会话文件装载到新沙箱；
- 回合结束后只回收允许持久化的文件和产物，然后销毁容器；
- 空闲会话不占用容器内存。

后续服务器扩容后增加按用户/会话复用的 warm pool，但安全边界不变。

必须隔离的状态：

- 文件与产物路径；
- 对话、任务和模型上下文；
- 环境变量、令牌和外部连接凭据；
- 浏览器 Profile、Cookie 和页面状态；
- 进程、网络、CPU、内存、磁盘和运行时间；
- 工具授权和审计日志。

## 6. SkillHub 模型

Skill 包支持标准 Agent Skill（顶层 `SKILL.md`）并允许 SkillGo 扩展清单。平台能力包括：

- 上传 ZIP、AI 识别资料、静态安全扫描；
- 不可变版本、哈希、权限快照；
- 私有、组织、非公开链接和公开社区；
- 发布审核、下载、收藏、安装、更新和派生；
- 兼容性、运行时、权限和验证状态徽章；
- 未来增加签名、可信发布者、评分和依赖锁定。

## 7. API 形态

目标统一入口：

`POST /api/v1/agent/responses`

请求包含自然语言、会话 ID、附件、可选 Skill 约束和同步/异步模式。响应支持：

- 同步 JSON；
- SSE 流式事件；
- 异步 `task_id`；
- 完成 Webhook；
- 产物下载地址。

网页和公开 Endpoint 使用同一套 AgentRun/Task/Artifact 事件，不维护两套执行逻辑。

## 8. 交付阶段

### 已实现基线（持续维护）

- 多工具调用；
- 推理轮数与工具操作数分离；
- 首页改为对话式任务入口；
- 任务详情继续使用现有 gVisor Worker；
- 本机代码作为唯一部署源。

### 近期增强

- 全局会话（不再先进入某个 Skill）；
- Skill 路由与按需加载；
- 会话工作区快照；
- 对话内任务卡片、产物卡片和 SSE；
- 工具输出裁剪与自动上下文摘要。

### 中长期演进

- 每用户独立浏览器/电脑工具；
- 权限审批中心和凭据保险库；
- warm sandbox pool；
- 多 Skill 编排、定时任务和 Webhook；
- Skill 安装、更新、派生、评分和签名。

## 9. 不可妥协的验收标准

- 用户 A 无法查询、下载、挂载或推理到用户 B 的任何状态。
- 没有真实工具结果和产物校验，任务不能标记成功。
- 相同 API 和网页调用产生一致的执行记录。
- Agent 达到推理、工具、时间或资源上限时可解释地终止。
- 本机仓库能从零构建并部署到新的 Ubuntu 服务器，不依赖服务器上的手工热修复。
