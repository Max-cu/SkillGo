# SkillGo 三批编排优化交付记录

日期：2026-09-07。基于本地 v0.2.6 代码完成三批优化；真实业务测评按用户安排，留到本轮实现完成后建立。

## 已实现

| 批次 | 实际变化 |
| --- | --- |
| 第一批：修复可靠性问题 | 专用验证器与真实文件绑定；失败写入使读取缓存和旧验证失效；有新结果的操作重新计算防循环窗口，成功空操作不能无限清零；可选文档命令不进入硬依赖预检；活动 Skill 不被历史压缩丢弃；工具参数无歧义规范化及错误类型容错。 |
| 第二批：任务状态与执行反馈 | 步骤依赖与实际输入输出哈希；文件变化使相关步骤和下游失效；保留成功标准与阶段证据；按上下文预算保留完整工具往返；完整大结果落盘；模型推理参数、预算、有限网络重试和原生工具兼容降级。 |
| 第三批：复杂任务流程 | 工作台自动选择 Skill 与零匹配错误；提问、等待、回答、重新排队；历史文本背景和已确认答案固化；固定脚本与 Agent 阶段混合运行；生成图片通过配置的视觉模型检查；执行计划与提问在页面展示。 |

固定入口模式已作为明确元数据提供给 Agent，平台拒绝未执行固定入口就登记该 Skill 完成。验证器必须对成功标准输出结构化实际观测，模型声明无法覆盖失败退出码或失效的文件哈希。

- 独立本地界面验收：自动选择开关、历史任务澄清表单、计划展开、回答后排队、模型适配与预算保存。

测试保留一条原有 Starlette/httpx 弃用提示，不影响结果。界面测试使用独立 SQLite、合成账号和本地无服务模型地址，临时浏览器页和测试服务已关闭。

回归包含真实运行循环和 Worker 生命周期，沙箱及模型由受控测试替身提供。它们验证平台执行语义，不能代表私有模型输出质量。后续服务器部署已验证 PostgreSQL 迁移及真实 gVisor 沙箱自检；真实业务金标准和实时视觉模型效果仍待测评。

## 使用与升级

1. 部署前运行项目既有数据库迁移流程至 `20260907_0007`，并同步更新后端、Worker 和前端构建。
2. 在平台设置按实际模型能力设置推理适配、推理强度、上下文和输出预算。视觉检查需要默认视觉模型以及任务所需的页面渲染工具。
3. 普通任务可在工作台开启“自动选择 Skill”；手动插入的 Skill 保持指定顺序。
4. 缺少必要业务参数时，任务显示问题；提交答案后从原始输入和全部已确认答案重新执行。

三批优化及自动选择开关修复已提交、推送并部署，本次归入 v0.3.0 版本。详细协议见 [Agent 内核](agent-kernel.md)。

## 业务测评需要判定的内容

下一步应测严格业务通过率、遗漏要求、示例数据污染、错误成功声明、定向修复成功率、耗时与 token。模型、Skill 版本、输入和预算应固定，保留旧内核对照，并以独立人工或程序金标准判断。

当前平台保证验证操作真实执行且绑定文件；不会自动证明验证程序已覆盖所有业务要求。自动召回使用词项相关性排序，复杂同义需求仍需测评。等待用户后采用新沙箱重跑，尚不恢复半成品工作区。任务内并发、分支隔离和子代理保留为根据实际评测需求再决定的扩展。
