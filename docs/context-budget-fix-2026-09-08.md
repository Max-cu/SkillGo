# 上下文预算修复

## 触发问题

任务 `683c5f0b` 第 2–9 轮请求只保留系统提示、用户原始请求和执行摘要，近期完整工具结果被丢弃；模型反复读取输入，摘要继续增长后第 10 轮触发 AGENT_CONTEXT_LIMIT。旧实现先为全部摘要分配预算，最近工具交互放不下时直接舍弃，仍继续调用模型。

## 修改

- 先保留固定提示、原始要求、计划和验证状态、活动 Skill 以及最新完整工具交互。工具调用 ID、参数及供应商推理字段保持不变；多工具交互整体保留。
- 摘要中的旧观察只保留路径、操作序号和状态等元数据，最多约 1024 个估算 token，并进一步服从剩余预算；正文和 stdout 不再重复放入固定摘要。
- 超过 4000 UTF-8 字节的工具结果完整保存至 `/workspace/work/tool-results`，模型收到最多 1600 字节正文摘录、状态及完整文件路径。外层消息仍为合法 JSON。
- 原生工具定义纳入输入预算估算；首次请求预留 2048 token 的反馈空间。无法容纳必要内容时立即明确失败，不发送丢失最近结果的请求。
- 每次 Agent 执行保存 `WorkflowJobMemory.data.model_budget`；推理事件记录预算各部分占用、所需最小预算、丢弃旧交互数量。失败预算检查也将该轮标记为失败并持久化诊断。
- 嵌入式 Alembic 迁移跳过日志重配置，CLI 迁移仍配置自身日志且不禁用已有 logger。

## 边界

预算是保守的 JSON UTF-8 字节估算，不等同于供应商精确 tokenizer。完整指南本身过大或最新单轮交互过大时仍会明确失败，需要选择模型真实支持的预算，不能据此自动扩大服务容量。本次未修改模型名称、连接、timeout、业务规则、验证门禁或任务总时限。

首次检查发生在沙箱准备完毕、第一次推理之前；不是上传或入队前的检查。预算快照是该次执行实际读取的配置；不追溯恢复已经删除的历史配置。
