# 素材准备


> **输入**：调用方提供的 `.zip` 素材包（后端统一打包，内含任意格式混搭：docx/pdf/pptx/xlsx/txt/md/散图，可能含多层嵌套 zip）；**或只给一句主题**（零素材 → §0d 联网取材）
> **输出**：`assets/sources/` 下的照片 + `assets/sources/文本.md`

从 zip 素材包递归解压、按文件类型分发处理，输出固定存入 `assets/sources/`。

---

## 前置条件

本步是**流程入口**，没有上游产物依赖，但要满足三条才能跑：

1. **素材就位，或确认「零素材 + 给了主题」** ——
   ① **有素材**：调用方提供了 `.zip` 压缩包（**只要用户在前端上传了文件，哪怕只有一张图片，后端也一律打包成 zip** ⇒ 这里**只认 `.zip`**，不存在「单个散文件 / 多文件 / 目录」的形态）；
   ② **零素材**：跳过 §0b，直接走 **§0d 联网取材**（判定见下文「执行顺序总表」）—— 形态含「只给一句主题」与「贴了一段文字」两种（后者缺省当**主题来源**，见 §0d）。
2. **`assets/sources/` 可写** —— 目录不存在时脚本会自动创建；若已有旧素材，§0a 会自动清空。
3. **工作目录 = skill 根目录** —— 脚本通过 `Path(__file__).resolve().parent.parent` 定位项目根目录，命令块里的 cd &lt;SKILL_ROOT&gt; 不能省。

> 素材准备是**全流程的地基**：提取不干净（少图、混入模板图），后面每一步都建立在错数据上。所以本步的验证（0e）和收尾（0i）都不要跳。

## 执行顺序总表（**先看这张表再动手**）

> **§0d 是条件分支，不是顺跑的一步** —— 「跑 / 不跑」由**这张表**决定，
> 判据是「**调用方给了什么**」+「**§0c 收尾量出的达成率**与**通读检查表**的结论」。
> 更细的判据 = **§0c 收尾的达成率**（体量缺口，脚本算）+ **§0d 的「通读检查表」**（事实缺口，通读判）；
> 本节只给**一站式导航**，两处口径一致。

| 顺序 | 子步骤 | 跑不跑 | 判据 / 备注 |
|---|---|---|---|
| 1 | **前置** 解析提示词标记 | **必跑** | 先于一切，解析 `[联网搜图]` / `[PPT风格]` |
| 2 | **§0a** 清空 `sources/` | **必跑** | 无分支 |
| 3 | **§0b** 解压提取 | **有条件** | **有 zip 才跑**（零素材 / 只贴一段文字 ⇒ **整步跳过，直接到 §0c**）。一条命令：`extract_all.py`（提取 ＋ **原文另存** `_local_source.md`） |
| 4 | **§0c** 统一结构化 | **有 zip 才跑** | 把**本地素材**提纯成「关系块 + 要点」、给每张图补「内容：」；**收尾量一次正文体量**（给 §0d 提供缺口数字）。**零素材没有本地段 ⇒ 整步跳过** |
| 5 | **§0d** 联网取材 | **有条件** | **见下表** —— 这是全流程唯一的分支点 |
| 6 | **§0e** 概览 + 校验 | **必跑** | 一条命令；**`文本.md` 被动过（§0c / §0d 跑过）就要回跑一次**（**此处可复核/重传 `--facade`**） |
| 7 | **§0f** 联网补图 | **有条件** | 缺省 ON，仅 `[联网搜图：OFF]` 时整步跳过 |
| 8 | **§0i** 完成收尾 | **必跑** | 中间产物已由 `extract_all.py` / `clean_research.py` 自动清理；零素材路径无中间产物 |
| 🔖 | **§0g** 图片占位符约定 | **参考** | **不在执行序列里** —— 写 `design_spec.md` 前读一遍即可 |
| 🔖 | **§0h** 失败处理 | **参考** | **不在执行顺序里** —— 出问题才回来查（症状表） |

> **🔖 那两行是「参考章节」，不占执行顺序** —— 所以 `g` / `h` 在执行序列上不连号。
> **序号 = 文档里的顺序 = 执行序列**（`§0a → … → §0i` 连续）：`pre → a → b → c → d → e → f → i`。
>
> 🔑 **为什么「量体量」落在 §0c 收尾、而不是 §0b** —— 本地素材在 §0c 会被**提纯**
> （原文 → 要点清单），**体量必然缩水**。若在 §0b 拿原文量，会出现：
> `§0b` 量出"达标" → §0d 判定不用跑 → 然后 §0c 把原文压成要点、实际不够了，
> **再没人量、也不报错** —— 静默漏判一路带到 Step 1 才以"内容量不足"炸出来。
> 所以必须**在提纯之后量**（§0c 收尾），量到的才是真实体量。

**§0d 跑不跑的判据（只有这五种，别自己当"缺口"去搜）**：

| 调用方给了什么 | §0b | §0c | §0d | 档位 |
|---|---|---|---|---|
| **什么都没给**（无素材 + 无主题） | 不跑 | 不跑 | **不跑 → 直接终止** | 终止并说明「请提供素材，或指明主题」 |
| **zip 素材**，检查表全过、体量也达标 | 跑 | 跑 | **跳过**（缺口清单为空） | — |
| **zip 素材**，有**事实缺口 / 体量不足** | 跑 | 跑 | **跑** | **定点补缺口** |
| **zip 素材**，但**正文为空**（里面只有图片） | 跑 | **只做配图**（无正文可提纯） | **跑** | **全量取材**（图片保留） |
| **只给主题**（或**贴了一段文字**——缺省当主题来源，先总结出主题） | 不跑 | 不跑 | **跑** | **全量取材** |

> **「检查表」与「体量」分别怎么来**：
> · **体量不足** → **§0c 收尾**那条 `verify_extraction.py` 直接给出**达成率与缺口 N 字符**（别靠通读估）；
> · **事实缺口** → 通读 `文本.md`，照 §0d 的「**通读检查表**」逐项过（脚本查不出这个）。
> 两者**任一命中**即进 §0d「定点补缺口」。

> **两条容易踩的**：
> ① 「**§0d 无开关**」说的是**它不能被提示词关掉**（区别于 §0f 的 `[联网搜图：OFF]`），
>   **不是**说"每次都必须跑" —— 素材够用时它就该**空转跳过**，硬搜属于越界（红线：不编造、不凑数）。
> ② **有素材时绝不能一上来就联网** —— 必须先 `0b` 转换 → `0c` 提纯，拿到**提纯后的真实体量与要点清单**，才知道缺什么（顺序依据见 §0d）。

## 执行步骤

### 前置：解析提示词标记（**先于一切**）

> **权威定义在 `SKILL.md` 的「前置」，本节只讲它对素材准备的影响。**
> （早期这里有一份独立副本，两处内容漂了 —— **2026-10-08 收敛为「以 SKILL.md 为准」**，别再各写一份。）

提示词末尾可能拼两个标记：`[联网搜图：ON/OFF]` 与 `[PPT风格：<风格 id>]`。
解析口径与缺省值见 `SKILL.md`；**对素材准备的影响**只有下面这些：

> 🔄 **改名提醒（2026-10-14）**：第二个标记原名 `[PPT主题：xxx]`，**现名 `[PPT风格：xxx]`**；
> **旧名仍识别、等价处理**（不会静默回退）。两处写法在本节其余文字里同义。

| 标记 | 缺省 | 影响素材准备的哪一步 |
|---|---|---|
| `[联网搜图：ON]` | **ON**（**2026-10-08 起缺省由 OFF 改为联网**） | §0f 执行与否 —— ON 才补图 |
| `[PPT风格：<风格 id>]`（旧名 `[PPT主题：…]` 等价） | `default`（**写了其它值也按它处理**） | **与素材准备无关** —— 只决定 Step 2 写 `_meta.palette` |

> **「联网取文」没有开关**（2026-10-08 用户拍板）—— 它是**固定路径**：
> 只要 §0d 判定"需要外部事实"就会执行；**不需要时自然不补**（素材够用 ⇒ 缺口清单为空 ⇒ §0d 空转）。
> 所以提示词里**没有**第三个标记，前端也不要拼。

**`[联网搜图：OFF]`（只能由调用方显式指定）意味着**：

- 素材里有多少图就用多少；
- 图量不足时**不联网找图**，直接进 Step 1，用**无图版式**消化内容
  （§5.2 多栏并列 / §5.4 表格式 / §5.6 卡片矩阵 / §5.10 编号条目列 / §5.3 流程链 … ——
  契约 §5.10.1 已解决"纯条目列填充率必然 0%"的问题，**无图页在技术上完全可行，不是降级方案**）。

> **判定依据只有提示词 / 任务描述这一处。** 素材包里**没有**配置文件，不要去 zip 里翻 `options.json` 之类的东西 —— 不存在。
>
> **OFF 就老老实实不搜。** 调用方显式写了 OFF 时，**不要**为了填满版面而自作主张去搜图，
> 也不要因为"图不够"而反复重试或报错 —— 这是**预期行为**，直接进 Step 1。
>
> **脚本的补图建议与开关无关**：`verify_extraction.py` 在「0 张 / 图量不足」时会**无条件**打印
> `fetch_web_images.py` 的命令建议（它是校验器，不知道开关状态）。
> **显式写了 OFF 时请忽略那段建议** —— 脚本输出里已标明「开关为 ON（缺省）时，直接运行以下命令」，
> **不要因为"脚本建议了"就去执行**，那正是 OFF 要拦住的默认行为。

### §0a：检查并清理旧素材

**操作**：运行以下命令，确保 `assets/sources/` 是干净的空目录：

```bash
cd <SKILL_ROOT>
python scripts/validators/check_sources_dir.py
```

**脚本行为**（三种情况都返回 exit 0，无需分支判断）：

| 情况 | 动作 |
|------|------|
| 目录不存在 | 创建 `sources/` 空目录 |
| 目录存在且为空 | 直接继续 |
| **目录存在且有旧素材** | **自动清空**（本 skill 以 API 黑盒方式调用，不做人工询问） |

**预期输出**（对应上表三行）：`✅ sources/ 不存在，已创建` ／ `✅ sources/ 存在但为空，继续` ／ `⚠️ sources/ 非空（N 项），自动清空旧素材` → `✅ sources/ 已清空（剩余 0 项）`。

> 必须清空：新的 `extract_all.py` 会自动清理中间产物，但旧的 `image_*.jpeg` 不会自动删除，残留会让新旧照片混在一起，导致后续配图错乱。

### §0b：解压提取（`extract_all.py`）

> **本步只有一条命令，「有 zip 才跑」**（没 zip 就整步跳过 → 直接到 §0d）。
> 它只做**格式转换**（解压 / 分发 / 转 Markdown / 收编散图 / 合并），
> **不碰内容** —— 提纯归 §0c、量体量也归 §0c 收尾（原因见「执行顺序总表」下的说明）。

**命令**：

```bash
cd <SKILL_ROOT>
python scripts/extract_all.py "<素材.zip 的绝对路径>"
```

**脚本内部做什么**（无需手工干预）：

| Phase | 动作 | 是否打印标题 |
|---|---|---|
| 1 | **递归解压** —— 解压 zip → `_extract_root/`；扫描到嵌套 `.zip` 继续递归解压（防同名冲突：用路径扁平化拼入前缀，如 `subdir_report.pdf`） | |
| 2 | **分类** —— 按后缀分为文档类（docx/pdf/pptx/xlsx）、文本类（txt/md）、图片类（散图） | |
| **2.5** | **依赖预检** —— 按已识别出的文件类型检查依赖是否装齐；缺则打印可直接复制的安装命令并**终止流程**（不让它跑到 Phase 3 才逐篇失败） | |
| 3 | **文档类转换** —— 调 `source_to_md.py` 逐篇转 Markdown，图片自动编号 → `sources/image_NNN.ext` | |
| 4 | **文本类直读** —— txt/md 直接读入（utf-8 失败回退 gbk） | |
| 5 | **散图收编** —— zip 中直接躺着的图片编号复制到 `sources/`，文末统一登记 | |
| 6 | **合并 ＋ 另存原文** —— 所有 Markdown 合并为 `sources/文本.md`，同时**一字不改**地另存一份 `sources/_local_source.md`（§0c 提纯前的**回溯底稿**） | |
| 7 | **清理** —— 删除 `_extract_root/` 和所有 `_tmp_*` 残留 | **静默执行**，只输出「清理完成」 |

**预期输出**（逐 Phase 打印，**文件名仅示意**，实际是你素材里的名字）—— 形状如下，末几行是判据：

```
🔍 Phase 1: 递归解压...   → 解压得到 18 个文件（逐个列出，含嵌套 zip，带包名前缀）
🔍 Phase 2: 分类...       → 文档类 5 / 文本类 4 / 散图 9
🔍 Phase 3: 文档类转换... → 逐篇 ✓（内嵌图编号为 image_NNN.jpeg）
🔍 Phase 4: 文本类直读... → 逐篇 ✓（N 字符）
🔍 Phase 5: 散图收编...   → 逐张 📷 image_NNN.jpg（散图: 原始路径）
🔍 Phase 6: 合并...
📝 合并文本: .../assets/sources/文本.md (3179 字符)
🗄 原文另存: .../assets/sources/_local_source.md (3179 字符，§0c 提纯前底稿)
✅ 提取完成: 5 篇文档 + 4 篇文本 → 14 张图片
🧹 清理完成
```

> **为什么多留一份 `_local_source.md`**：§0c 会把 `文本.md` 的正文区**整段替换**成
> 提纯后的要点清单 ⇒ 原文就此从 `文本.md` 消失。留一份**一字不改**的原文，
> 一是**可回溯**（提纯结果对不上原文时能查证），二是它是调用方「既定内容」的凭证。
> ⚠️ 它是**正式产物**，不在任何清理范围（`clean_research.py` 不会动它）。

> **查看 zip 内容一律用 Python**，不要用 `ls` / `unzip -l`：
>
> ```bash
> python -c "import zipfile; [print(i.filename) for i in zipfile.ZipFile('&lt;zip路径>').infolist()]"
> ```

### §0c：统一结构化（**本地素材提纯 + 图片说明**）

> **一句话**：把本地素材**当抓取件处理** —— 跑与 §0d（联网取材）**同一套流水线**，
> 唯一多出来的只是「它可能带图」这一步。
>
> **本步治的是「两条取材路出口形态不一致」**：取材有两条路（§0b 本地素材 / §0d 联网取材），
> 但下游只认**一种**形态 —— `文本.md` 里**每块内容都带逻辑关系标注**、**图片带含义说明**。
> 联网那条由 §0d D 的 `#GROUP` 自动生成；本地这条此前**什么都没产出** ⇒ Step 1 只能退到
> 最弱的默认「并列」，于是 **R1 / R2 / R3 / R6 / L1~L3** 这些**按关系触发的组件与骨架系统性用不上**。
> 散图更只有「目录 + 文件名」、**零语义**（`IMG_20260830_113245.jpg` 让 Step 1 无从选图）。

**两条路其实只有一处不同**：

| | 来源性质 | 怎么处理 |
|---|---|---|
| 联网素材（§0d） | 抓回来的是**网页原文**（几万字、混着导航与重复） | **浓缩**成 claim 清单（`[G…]` 段） |
| 本地素材（本步） | 调用方给的**正文**，但它仍是**待加工原料**、不是成品 | **同样提纯**成要点清单（`[L…]` 段）；原文另存 `_local_source.md` 留档 |

> ⚠️ 别把病根认成「两条路浓度不同」—— 浓度不同本身不是 bug。缺的是**出口形态**：
> 两边都得给出「这块内容是什么关系」。

**四步做完：① 提纯 → ② 配图 → ③ 落盘 → ④ 量体量（⑤ 清临时件）**

#### ① 提纯 + 标关系 —— 写 `assets/sources/_local_facts.txt`

通读 `assets/sources/文本.md`（= §0b 解压出的原文，与 `_local_source.md` 同内容），
按**已有标题层级**切块（连续无标题段落算一块），逐块压成**要点清单**。

> 🔴 **不是每块都得有 `#GROUP`** —— **能归组的才归组**；确实孤立、与别的块没有结构关系的，
> **留在组外当散点**即可（与 §0d D 那句「**不必条条归组**」是同一条规矩）。
> 🔴 **散点要写在第一个 `#GROUP` 之前** —— `#GROUP` 管到下一个 `#GROUP` 为止、**普通行不会重置管辖**
> ⇒ 夹在两条 `#GROUP` 之间的「无组行」会被**前一组静默吞掉**（渲染成那一组的事实、不报错）；
> 只有写在**所有 `#GROUP` 之前**才是真散点。
> ⚠️ **别为了「每块都有标注」硬凑组** —— 那会把无关内容塞进「并列」，下游照着它选出多栏并列，
> **等于替你把无关的东西摆成了并列结构**（`step_1_design_spec.md` §1b 有同款告警：「别把无关的散点硬凑成结构」）。

清单格式与 §0d D **完全同形**（脚本同一套解析）：

```text
#GROUP L1 | 并列 | 项目概况
L001 | 站址位于营口港区，设计年接卸能力 600 万吨，配套 2 座 20 万 m³ 储罐 | 项目概况 | 现场实训素材.docx
L002 | 一期建设 4 座 22 万 m³ 全容式储罐，设计年接卸 600 万吨 | 项目概况 | 现场实训素材.docx
#GROUP L2 | 时序 | 高处作业安全培训
L003 | 坠落高度基准面 2m 及以上即为高处作业，须全程使用五点式安全带 | 安全培训 | 现场实训素材.docx
```

> 🔴 **编号前缀 `L` 不能省，也不要为了「让脚本过」改成 `F`**（2026-10-18 实测）：
> 本地段用 `L001`、网络段用 `F001`，脚本**两种都认并原样保留**。
> 早期版本只认 `F` ⇒ `L001` 被当成「行首漏编号」整行右移，`claim` 变成 `L001`（4 字符）、
> 真实要点掉进别的槽位，**rc 仍为 0，静默产出垃圾**。平台实测报「平均 4 字符/条」、
> 正文只剩 `- L001` 三行，模型自己排查 4 次才定位到是格式问题（多花约 5 分钟）。

- **字段用 ` | ` 分隔**：`fact_id | 要点 | <块名> | <素材名>`。
  🔴 **本地不做溯源 ⇒ 最后一个字段留空也行**（网络段强制带 URL，那是红线）。
- **`#GROUP <块id> | <关系> | <块名>`** 管到下一个 `#GROUP` 为止；**块 id 用 `L` 前缀**
  （网络段用 `G`）—— 渲染成 `### [L1] 并列 · 项目概况`，与网络段**语法同形**。
- **关系值只能取这六个**（与 §0d D **同一张表**，别自造）：
  `并列` ｜ `构成` ｜ `对比` ｜ `递进` ｜ `时序` ｜ `分层`。
  🔑 **六个值各自的判据（含「对比 = 恰好两项」「构成 = 各项有占比 / 数值」这类硬条件）见 §0d D 的判据表** —— 标错关系，下游会照它选错组件（组件选型全部以关系为触发判据）。
- **要点要「写足」**：带**具体数字 / 条件 / 适用范围**，让它能**直接当内容页的一句正文**。
  ⚠️ **「写足」≠「全都要用上」**：一组 6 条、页面只用 4 条**是常态** —— 取舍见 `step_1_design_spec.md` §1b。
  🔑 **量化口径与 §0d D 第 5 条同源**（🔴 **改一处必须改另一处**）：**条数 = 内容页数 × 4、每条 ≥ 50 字符**
  （`--pages 15 --facade 7` ⇒ 8 × 4 = 32 条 / 1,600 字符）。
- 🔴 **原文不删、不改** —— 提纯只**新增**一份清单；`文本.md` 的正文区在 ③ 才被整段替换
  （原文已在 `_local_source.md` 留档），所以**不必"先备份再动手"**。

> **没有正文时（zip 里只有图片）**：跳过 ① / ③，**只做 ②**，然后直接进 ④ 量体量
> （量出来必然 ≈ 0 ⇒ §0d 走「全量取材」）。

#### ② 配图说明 —— 写「内容：」并把图挪出正文

> 🔴 **必须在 ③ 之前做完** —— ③ 会整段替换 `文本.md` 的正文区，
> 正文里残留的 `[[image_NNN]]` 会**随旧正文一起被替换掉** ⇒ 占位符数 ≠ 图片数、
> §0e 当场报错（**fail loud，不是静默丢图**，但白跑一轮）。

1. **写「内容：」说明**（「这是什么场景 / 拍的什么」）—— 🔴 **按图片来路两分，别一律逐张打开**：
   - **文档内嵌图**（原文自带图注，如 `图1 海水泵房现场施工图(a)`）⇒ **直接据图注写，不必打开图片**
     —— 可精炼、可补专业术语，但**语义以图注为准**。
   - **zip 散图 / 无图注 / 图注笼统**（文件名如 `IMG_20260830_113245.jpg`，或图注只写「现场照片」）
     ⇒ **才需要看图**（Read `assets/sources/image_NNN.*`）—— 文件名推不出东西时，看图是唯一线索。
   🔴 **不要「逐张看完再统一写」** —— 有图注的图**一张都不用开**；看过的也只需写一句，
   **不必「核对无误 / 一致」式复述**（那是纯输出开销，不产生任何新信息）。
2. **把图片全部收进文末 `## 附加图片` 登记段**（正文里不再留任何 `[[image_NNN]]`）：
   - **文档内嵌图** → 改登记行为 `[[image_001.jpeg]]（内嵌图 | 内容：脚手架拆除现场）`
     （原来跟着它的「图N …」图注**并进「内容：」**，别丢）。
   - **zip 散图** → 在原有三段后**追加** `内容：…`：
     `[[image_006.jpg]]（散图 | 目录：/ | 文件名：IMG_1.jpg | 内容：罐顶阀门检查）`。

> ⚠️ **`内容：` 是新增字段，不改原有字段**（「散图 / 内嵌图」「目录 / 文件名」照旧）——
> `check_materials.py` 靠这些词分类、`verify_extraction.body_only()` 靠**行首** `[[image_…]]`
> 整行剥除（加了 `内容：` 仍能正确剥掉，不会被算进正文体量）。

### §0d：联网取材（文本素材）

> **本步「跑不跑」前面已定** —— 走 **§0c 收尾**的达成率 + 「通读检查表」，**符合条件才进来**。
> 进来之后**从上往下照做**。**不需要外部事实时本步自然空转**（判据见「执行顺序总表」）。
>
> **唯一例外**：调用方**直接给了 URL**（少见）⇒ **跳过 A / B，直接进 C 抓**。

#### A. 先定位：本步要补什么

| 进来的原因 | 补什么 | 检索词来源 |
|---|---|---|
| 有素材 + **事实缺口** | 只补缺的那几块 | **缺口清单** |
| 有素材 + **体量不足** | 补内容撑页数 | 缺口字符数对应的板块 |
| **正文为空**（只有图片）/ **只给主题** | 从零建全部正文 | **主题本身** —— 见下方注意事项 4 |

**注意事项**：

1. **缺口的定义只有一条**：不做外搜就只能「编造 / 省略 / 含糊带过」的、且**外部可验证**的事实。
   行业现状 / 标准号 / 技术参数 / 公开数据 = 缺口，**去搜**。
2. **「外部不可验证」不是缺口**：「我们公司 Q3 进展」这类内部信息，外搜查不到 ⇒ 是**素材没给**
   ⇒ **终止并说明**，别硬搜。**素材长短、文件多少都不构成判据。**
3. **前两档有退路**（原素材还在，补不到就少讲）；**后一档没有** ⇒ 搜不到实质内容**必须终止**。
4. **「拆板块」≠「拆检索词」** —— 只有主题时把它拆成 3~5 块，是**画面规划**的事（Step 1 干）；
   **检索一律按 B 段规则只取 1 个核心实体**。**不要把主题拆成几组词分头去搜**：
   主题形如 `A：B 与 C` 时最容易犯 —— 把 B、C 各当成一组检索词，于是第 2 条词变成 `A B`
   （核心词 + 通用词连写）⇒ **必被必应切碎**，后面每条词跟着废
   （实测：5 条词全废，最终只有 2 篇可用、体量达成率 63%）。

#### B. 找 URL（必应为主战场）

```bash
python scripts/source_to_md/web_to_md.py --search "<核心词>" --limit 10    # 输出 标题<TAB>URL
```

**取词注意事项**：

1. **只给 1 个短核心词**（2~4 字）—— 剥掉修饰语与副标题，只留最核心的那个名词。
   例：`城市地下综合管廊：分类、系统构成与施工工法` ⇒ **`综合管廊`**。
   判据是「**每个词是不是专有实体**」，**不是「几个词」**；**能少优先于够全**。
   **主题有多个方面也不许拆组**：一次只搜一个核心实体，覆盖不到的方面靠**换词阶梯**逐轮补（见下）。
2. **主题副标题里的词一律不许进查询词** —— `工艺流程` / `分类` / `工法` / `系统构成` /
   `报告` / `综述`，以及副标题里那种**修辞化的短语**（抽象名词堆叠、带情绪或愿景色彩），
   这类**看着像主题、其实是通用词**，一加就把专有实体冲掉。
   完整禁词表见 §0f「取词铁律」。
3. **必应走 RSS、结果已按来源分级排序**（官方 / 媒体优先，百科 / 内容站沉底）⇒ **从上往下取**。
   **切碎是常态，不等于「必应这条路没戏」** —— 实测一个 4 字词也被拆成词典 / 地图页。
   切碎只说明**这一条词**不行 ⇒ **按换词阶梯换下一条（先往"泛"换，见下表）继续试**，
   **别因一次切碎就跳过剩余预算**（实测：只试 2/6 条就跳走，剩下 4 条本可试同族实体）。
   脚本会打 `[WARN] 查询词疑似被切碎` 并给建议短词（`综合管廊 分类` ⇒ `综合管廊`）⇒
   **先照它重试；词已经够短（≤4 字）就直接换同族实体**，别在原词上纠缠。
4. **`site:` 语法在百度 / 必应 / 360 / 搜狗都失效**，别用。

**换词 —— 只在下面三种情况才换**：① 没搜到正文页 ② 搜到了但抓不成正文 ③ 结果跑题。
**结果里有正文页、只是还没抓 ⇒ 先抓，别换词。**

> 🔴🔴 **先看主题本身能不能检索到（2026-10-18 实测）** —— 这一类失败**换词救不回来**，
> 因为不是"词不对"，是"这个说法在必应里就没有正文"：
>
> | 主题形态 | 例 | 实测结果 | 建议 |
> |---|---|---|---|
> | **具体对象 + 动作** | `动力电池回收` / `沉管隧道施工` | ✅ 一次命中工信部、发改委、人民日报 | **首选** |
> | **行业 + 抽象体系** | `城市轨道交通智能运维` / `化工园区双重预防机制` | ⚠️ 6 条词全废：交通部栏目页是壳页、"智慧地铁"被泛化成教育平台、"地铁"返回地图站、"轻轨"返回辨析科普 | **拆出具体对象再搜**（`地铁隧道监测` / `动力电池回收`） |
> | **纯概念 / 愿景词** | `数字化转型` / `高质量发展` | ❌ 返回政策解读与评论，无具体事实 | **换题** |
>
> **判据**：把主题里的"体系 / 运维 / 建设 / 管理 / 智能化"这类词去掉，**剩下的那个名词还能不能指向一个具体的东西**。
> 指向不了 ⇒ 这题在公开网络里大概率没有正文，**早换角度比烧完 6 条词再换划算**。
> ⚠️ 这里说的是**换主题角度**（这题本身没正文），**不是提前切通道** —— 通道要等 6 条词打完才切，别混。
>
> 🔴🔴 **切通道只在「通道不可用」时触发，不是「搜得不好」就切（2026-10-19 修正）**
>
> **必应返回了结果但内容不行**（壳页 / 被切碎 / 全是短视频 / 跑题）⇒ 这是**词的问题，通道是好的**
> ⇒ **继续按换词阶梯换下一条，6 条预算该用完就用完**，不要提前走。
> 只有**两种情况**才切通道 2：**① 网络报错**（`[ERROR] cn.bing.com…`，脚本会打 HINT）
> ／ **② 6 条词打完仍凑不够体量**。
>
> 依据（2026-10-18 实测复核）：某主题的 6 条词当时被判「全废」，但逐条看**每一条都有返回** ——
> 壳页 1 ／ 重叠 1 ／ 跑题 1 ／ 切碎 2 ／ 空 1 ⇒ **必应全程可用，坏的是选词**。
> 用"切通道"去治"选词"，代价是提前放弃优质通道：必应结果按来源分级（官方 / 媒体优先），
> 而该次最终 5 篇全部来自同一个行业站（ofweek.com）—— **单源内容，换来的是 3 分钟**。
>
> **6 条词预算用完后**：脚本会 `[STOP]`，此时**只能**走 **`--list-links` 栏目页通道**；
> 栏目页也提不到 ⇒ **按 §0d 红线终止并说明**，并**明确告诉调用方"这个主题公开网络缺正文，建议改搜 X"**——
> 别硬凑无关内容，也别拿百科条目当正文。

**换词方向：先往"泛"走，再往"细"走** —— 这个顺序是 2026-10-18 平台实测之后定下来的，别调回去。

| 档 | 方向 | 换什么 | 例（管廊题 / 氢能题） |
|---|---|---|---|
| 1 | — | **核心实体**（剥光修饰语）| `综合管廊` · `氢能储运` |
| 2 | ⬆ **先往泛** | **上位实体**（比原词更泛的同类）| `管廊` / `地下工程` · **`氢能` / `储氢`** |
| 3 | ⬇ 再往细 | **下位"具体实例"**（地名 / 项目 / 企业 / 型号）| **`广州地铁`** / `港珠澳大桥` |
| 4 | ↔ | **伴生**（上下游、配套设备）| `预制拼装` / `储罐` · `加氢站` |
| 5 | ↔ | **机构 / 标准号** | `住建部` / `GB/T 50838` |
| 6 | ↺ | **反向词**（难点 / 事故 / 争议）| `管廊 运营 难题` |

> 🔴🔴 **为什么「上位」必须排在「下位」前面（2026-10-18 平台实测）** —— 旧顺序是先下位，结果是这样：
>
> 主题「氢能储运技术路线」，**6 条词 0 有效结果**：
>
> | 序 | 词 | 结果 |
> |---|---|---|
> | 1 | 氢能储运 | 国家能源局 PDF/HTML，**369 字符壳页** |
> | 2 | 氢气储运 | 与上一条**重叠**（同义改写，白烧一条）|
> | 3 | 液氢储运 | 全是**短视频** |
> | 4 | 高压气态储氢 | 被必应**切碎成「高压」** |
> | 5 | 固态储氢 | **也被切碎** |
> | 6 | 掺氢天然气管道 | 空 |
>
> ⇒ **纯技术名词的下位越走越窄**：词越长，必应越容易切碎。
> 反过来，**上位泛词（`氢能` / `储氢`）结果多，而且里面带栏目页**，能直接接通道 2。
> ⇒ **同义改写（氢能→氢气）不算换档** —— 脚本会打「重叠」，看到就当这条已经废了。

> 🔴 **「下位」有两种，效果差很远**：
> · **通用子类**（`地铁` / `轻轨` / `高速公路`）—— 必应返回**百科与辨析科普**，取不到正文；
> · **具体实例**（`广州地铁` / `港珠澳大桥` / `宁德时代`）—— 才有媒体报道与官方数据。
> ⇒ **下位只认"具体实例"**；**纯技术名词（`固态储氢` / `高压气态储氢`）不算具体实例**，不许当第 3 档用。
>
> 🔴 **方面词会被脚本 REJECT**（建设 / 发展 / 现状 / 技术 / 运维 / 管理体系…）——
> 这类词一加，必应就把长词切碎。**换词要换"实体"，不是往旧词上叠方面词**；
> 加**具体限定**（城市名 / 地名 / 型号）则放行，脚本会打 `[OK] 判为下位实体`。

**换词注意事项**：

1. **换的是实体维度，不是措辞** —— 同义改写只会搜回同一批页面，白费一条词
   （脚本会打 `[WARN] 与上一条词重叠 N%`，**看到就当这条词已经废了**）。
2. **候选从哪来（按优先级）**：① **上一轮结果的标题**里那个比原词更具体的实体名
   ② 已抓到正文里的术语 ③ 机构名 / 国标号 ④ 你自己的领域知识。
   **不要回头去抓主题副标题里的词** —— 这是第 2 条词最常见的翻车点：第 1 条命中壳页后，
   模型会回头把副标题那个修辞化短语**改写成一条长句** ⇒ 必应必然切碎，结果全是垃圾。
3. **两条判据都要过**：① 与上一条词**搜出来的东西不一样** ② 候选词**单独搜能指向同类实体**
   （能：`接收站` / `核电站` / `储罐`；不能：`工艺流程` / `分类` / `报告`）。
4. **剥光后太泛**（只剩缩写 / 泛称，如 `LNG` / `氢能`）⇒ **再补 1 个专有实体落地**
   （`LNG` ⇒ `LNG 接收站`）。**补的必须是专有实体** —— 方向与「加通用词」完全相反。
5. **禁止的换法**：加修饰语 ／ 加通用词 ／ 换公司 / 品牌名（命中官网、招聘、股价页）／ 长句（> 8 字）。
   **脚本会当场拦**：往旧词上叠词的（`核心词 + 方面词`）会被打 `[REJECT]` 并**跳过执行**
   （不白搜，但预算照扣）—— **看到 `[REJECT]` 就是"你又在加词"**，换成另一个实体再试。

**通道 —— 三条，预算由脚本卡死**：

| 序 | 通道 | 预算 | 做法 | 何时换下一条 |
|---|---|---|---|---|
| 1 | **必应**（主战场）| **6 条词** | `web_to_md.py --search "<核心词>" --limit 10` | 素材够用 ／ **通道不可用**（网络报错）／ 预算用尽 |
| 2 | **栏目页路线** | **3 个 URL** | `source_to_md.py "<栏目页URL>" --list-links --limit 20` → 批量抓 | 试完 3 个仍提不到文章链接 |
| 3 | **360 探针**（**不计通道序位**）| **1 次** | Python 取 `https://www.so.com/s?q=<词>`，**只从标题里**挑「像栏目页」的 | 挑不出像栏目页的 URL |

**通道注意事项**：

1. **换通道 ≠ 换词** —— 只改 `--search` 引号里的词，你**还在通道 1**。
   三条通道的**调用形式完全不同**（`--search` ／ `--list-links` ／ `so.com`）。
2. **预算由脚本卡死，不用自己数** —— 每次调用先打 `[Budget] 已用 N/上限`，
   **超了直接打 `[STOP]` 并以 `rc=2` 拒绝执行**。**看到 `[STOP]` 就是真到头了**
   ⇒ 按红线「终止并说明」，**不许换个词再试**。
3. **通道 2 挑页优先级**：① 主责机构 / 厂商官网（正文完整、非 JS 渲染）→ ② 权威媒体频道页
   （**别用首页**，首页提链只有当日杂新闻）→ ③ 通道 3 探针给出的站名。
   **通道 2 的首选入口是「就地取材」**：必应结果里出现过「像栏目页」的 URL
   （域名层级浅、路径以目录结尾）⇒ **直接拿它走通道 2**。**绝不要靠记忆手拼文章 URL**。
   🔴 **什么时候才转通道 2（2026-10-19 修正）**：**6 条词打完仍凑不够体量**、
   或**必应网络不可用** —— 两者之一才转。**不要因为"前两条搜得不好"提前切**（内容不行 ≠ 通道不行，见上）。
   转过去之后**优先用「就地取材」那个 URL**（必应结果里出现过的栏目页），别自己另找站点、更别手拼文章 URL。
   实测：OFweek / 行业门户这类栏目页 `--list-links` 一次能提 20 条，命中率远高于继续换词。
4. **通道 3（360）只取标题，别碰它的链接** —— `so.com/link?m=…` **一律抓不成**（沙箱实测全 400）；
   **也不许写 Python 去解析重定向**（连试两轮全败）。看到 400 ⇒ **立刻放掉这条通道**。
5. **预算全用尽仍 < 1 篇可用 ⇒ 终止并说明**（见本步红线）。
   **本 skill 无交互，不存在「请调用方给 URL」**。

**候选过滤**：优先 `*.gov.cn` / 主流新闻域名；跳过 `baike.baidu.com`（403）、
`wenku.so.com`（JS 壳页，0 字符）、知乎 / 马蜂窝等 SPA。**未知域名抓一次试**（判据见 C 段）。
返回的**多是「网页」不是「文章」**（首页 / 栏目页）⇒ 像栏目页的走通道 2。

#### C. 抓正文（一个 URL 一条命令）

```bash
cd <SKILL_ROOT>
python scripts/source_to_md.py "<URL>" -o "assets/sources/_research/研究_<slug>.md" --no-images
```

**注意事项**：

1. **`--no-images` 必须带** —— 否则落 `_files/` 伴生图目录，**污染图片池**（图片另有 §0f）。
2. **不要为「准备目录」单开一条命令**（**别写 `mkdir -p`**）—— 脚本**自己会建父目录**；
   平台上每次工具调用都要走一轮确认，这条多余的 `mkdir` **实测白烧过十几分钟**。
3. **不许自己写 Python 抓** —— 那样内容**不进 `_web_text_facts.json`** ⇒ **溯源链断**（违契约 §1.6）。
4. **抓一篇判一篇，连丢 2~3 篇就回 B 段换通道**（**别攒批盲抓**）。**判据全在脚本 WARN 里**：

   | WARN | 含义 |
   |---|---|
   | `body is only N chars - looks like a shell page` | **N < 200** ⇒ SPA / 验证页 / 404 壳页 |
   | `body is N chars but only M of them (P%) read as prose` | **栏目壳页** —— 长度够，但绝大多数是链接与导航 |
   | `only N of M chars (P%) are Chinese` | **反爬页**（WAF 挑战页）—— 正文是混淆 JS，**整站都这样** |

   **看到任一 WARN 就丢弃该篇**，不用自己估。
   ⚠️ **换的是「域名」，不是「同一站的另一篇」** —— 实测（10-13）模型在一个反爬站**内部**
   换了 **13 篇**，篇篇撞同一堵墙。**反爬 / 壳页是站点级的，换文章没用。**
   **脚本会替你盯域名**：同一个站连续 2 篇不可用 ⇒ 打 `[STOP]`，之后再抓它的链接会被**直接拒掉**。
   **看到 `[STOP]` = 这个域名整体废了** ⇒ 回必应结果里挑**另一个域名**的链接，或按换词阶梯重搜。
   注意**字符数够、占比高也未必是正文** —— 栏目壳页与反爬页都可能上万字符 ⇒ 拿不准就**读一眼头几段**。
5. **日志走 stderr**（stdout 只有 `OUTPUT: <路径>` 一行）—— 看警告要连 stderr 看。
6. **依赖**：`requests` + `beautifulsoup4`（**必需**）、`curl_cffi`（可选，自动降级）；缺必需依赖会 **exit 1**。
7. 脚本会**无条件**生成 `<同名>.conversion_profile.json`（本 skill 用不上）—— 一并交给 E 段清掉。
   抓取落点 `_research/` 是临时区，**第 E 步会整个删掉**。

**抓够了没有？—— 跑一次体量估算再往下走（只读脚本）**：

```bash
python scripts/validators/check_research_volume.py --pages 15 --facade 7
```

- 扫 `_research/*.md`，逐篇算「净正文」并判壳页（判据与上面的 WARN 同源），**直接给结论**。
- **判据：净正文 ≥ 5,000 字符 且 可用 ≥ 3 篇。**
- **抓够 3~4 篇跑第一次；看到「够了」就立刻进 D 段** —— 别再「我觉得还不够」地接着换词。
- **别「抓一篇、量一次」**（每次调用都要一整轮思考）；不够就再补 2~3 篇、跑第二次。
- 若已换过通道、确实搜不到更好的源 ⇒ **带着它的数字直接进 D 段**，用 §0e 的真实体量再判一次。

**从栏目页提链**（拿不到文章 URL 时的正解）：

```bash
python scripts/source_to_md.py "<栏目页URL>" --list-links --limit 20    # 输出 标题<TAB>URL
```

- 文章 URL **猜不中**（实测猜 3 次全败）；栏目页 URL 稳定得多 ⇒ 「栏目页 → 提链 → 批量抓」。
- 打印 `WARN 这些链接看着都不像文章页` ⇒ 该页是 **JS 渲染**，**换一个栏目页**。

#### D. 落 `_web_text_facts.json` + 同步 `文本.md` 网络段（**一条命令出两份产物**）

> **本步你（模型）只产一个文件** —— 下面两份下游产物**全由脚本渲染**。
> 同一份 facts 渲染两份 ⇒ `facts.json` ↔ `文本.md` 网络段**一一对应由构造保证**，不用你维持。

**① 你唯一要写的 —— `assets/sources/_research/facts.txt`**（纯文本，一行一条）：

```text
F001 | <一句可直接用于 PPT 的事实陈述> | <来源页面标题> | <URL> | <抓取日期>
F002 | … | … | … | …
```

**⚠️ 光有事实还不够 —— 事实**之间**的关系必须在这里标出来（`#GROUP`）**

平铺的 fact 列表丢掉的，恰好是下游最需要的东西：契约的**组件与骨架选型全部以
「这块内容是什么逻辑关系」为触发判据**（②册 §4.8「R1~R6 路由判据」、③册 §5.0
「骨架选择速查」的「手上的内容」一列）。清单里没有关系，Step 1 就只剩最弱的默认
「并列」⇒ **R1 进度条 / R2 环形占比 / R3 VS 对比卡 / R6 递增柱 / L1~L3 时间轴**
这些**按关系触发的组件会系统性用不上**（2026-10-12 实测：R1~R6 在真实产物里**零引用**）。

🔑 **关系只有此刻标得出来** —— §0d E 紧接着就把整个 `_research/`（含全部抓取原文）
删掉；到 Step 1 时手上只剩平铺 claims，**连反推关系的原料都没有了**。

写法：在事实前加一行 `#GROUP <组id> | <关系> | <组标题>`，它管辖**直到下一个
`#GROUP` 为止**的所有事实：

```text
#GROUP G1 | 构成 | 中国 LNG 接收站储存规模增长
F001 | 2020 年液态储存规模 1,070 万 m³，到 2025 年达 2,868 万 m³，五年增长 168% | 央视新闻 | https://… | 2026-10-18
F002 | 2025 年接收能力 1.6 亿吨/年，2030 年目标 2 亿吨/年 | 央视新闻 | https://… | 2026-10-18
#GROUP G2 | 时序 | 卸船作业全流程
F003 | 靠泊后先进行船岸通讯，确认系泊状态与卸料臂对位，双方签字后方可接臂 | 上海应急 | https://… | 2026-10-18
```

**`<关系>` 只能取这六个值**（它们就是契约里真实存在的出口，**别自造**）：

| 关系 | 什么时候用 | 下游首选出口 |
|---|---|---|
| **并列** | N 项等价，无高下、无先后 | §5.2 多栏并列 / §5.6 卡片矩阵 |
| **构成** | 同一整体下的部分，各项有占比 / 数值 | R1 进度条 / §5.9 不等宽主分区 |
| **对比** | 恰好两项（或两组）逐条对照 | R3 VS 对比卡 / §5.18 双图对开 |
| **递进** | 后一项比前一项更高 / 更细 / 更关键 | R6 递增柱 / L2 阶梯轴 / §5.15 阶梯 |
| **时序** | 有明确先后 / 阶段顺序 | §5.3 流程链 / L1 中轴交替 / L3 阶段色带 |
| **分层** | 一层包一层、上下位包含 | §5.10 编号条目列 / §5.19 环形放射 |

> · **一个 `#GROUP` 管到下一个 `#GROUP` 为止**；组标题可省 —— `#GROUP G1 | 并列 |` 也认。
> · **不必条条归组** —— 确实孤立的事实留在组外就行（它只是散点，不会被当成结构输入）。
> · 🔴 **散点必须写在第一个 `#GROUP` 之前** —— `#GROUP` 管到下一个 `#GROUP` 为止，且**普通行不会重置管辖**
>   ⇒ 夹在两条 `#GROUP` 之间的「无组行」会被**前一组静默吞掉**（渲染成那一组的事实、不报错）；
>   只有写在**所有 `#GROUP` 之前**才是真散点（渲染成段标题下的无标题条目）。
> · 落盘时脚本会打一行 `→ 关系覆盖：N 组（构成×1 / 时序×1 …）`；**显示 0 组就是漏标了**，
>   回上面补 —— ⚠️ 但要赶在 §0d E 清掉 `_research/` **之前**。
> · 关系靠**读懂原文**判断，脚本给不了 —— 这是本步最有价值的产出之一，别只当格式要求。

> 🔴 **第一列的 `F001` 编号不能省**（2026-10-18 实测）—— 脚本靠它定位每条事实的起始位置。
> 漏掉编号、只写「事实 | 标题 | URL | 日期」⇒ 列会整体左移一格，**URL 被当成日期解析**，
> 结果是 `带 URL = 0/23`，而事实本身一条没丢、也不会报错 —— **静默失败**。
> 五列的顺序固定：`编号 | 事实 | 来源标题 | URL | 抓取日期`，**少一列就错位**。

**路径与格式注意事项**：

1. **路径固定为 `assets/sources/_research/facts.txt`**（**别放别处、别省成裸 `facts.txt`**）——
   `_research/` 是 E 段**必然整目录清空**的临时目录，写在里面才会被自动带走；
   放到 `assets/sources/` 根下**只会静静留到终态**（清理脚本不管它，也不报错）。
   **命令里的路径必须与写入路径一致** —— 脚本按 cwd 解析，写 `facts.txt` 会报「读不到」，白跑一轮。
2. **不要自己写 JSON、不要自己写 Python、也不要手写 `文本.md`** ——
   手写 JSON 踩引号坑已实测第 4 次。
3. 字段用 ` | `（空格-竖线-空格）分隔；`来源标题` 与 `抓取日期` 可省（日期省了用当天）；
   空行与 `#` 开头的行被忽略。**`claim` 里想怎么用引号都行**（`"` / 「」），**不用转义**；
   唯一要避开的是 `空格-竖线-空格`（会切成两段）。
4. **提炼要「穷尽」**：凡**外部可验证**且**可能用上**的事实**都登记**，**宁多勿少**
   —— 「哪几条最终写进 PPT」的决定在 **Step 2**，素材准备看不到。
   （**多登记的不会浪费**：一组 6 条、页面只用 4 条**是常态** —— 素材是**为适配组件而取舍**的，
   取舍在 `step_1_design_spec.md` §1b 按重要性做，见那里的 ⚠️。）
5. 🔴 **一条要「写足」，别压成口号**（**这条最费时间，务必一次到位**）：
   抓取件的净正文通常几万字符，**只提炼出 1~2 千就是压得太狠**。每条 claim 要带上
   **具体数字 / 条件 / 适用范围**，让它**能直接当内容页的一句正文**：
   - ❌ 太短（必定返工）：`高处作业必须系安全带`
   - ✅ 写足：`坠落高度基准面 2m 及以上即为高处作业；安全带须挂在作业面上方牢固构件上，严禁低挂高用`
   🔑 **量化口径：条数 = 内容页数 × 4，每条 ≥ 50 字符**
   （`--pages 15 --facade 7` ⇒ 8 × 4 = 32 条 × 50 = 1,600 字符）。
   ⚠️ 写不足会被脚本 WARN 挡回来重写一遍 —— **一次写足比分两次补便宜得多**。
6. **`source_url` 不能空** —— 只记**实质支撑**该事实的 URL；不许记没打开过的搜索结果（脚本会拦）。
7. **别忘了 `#GROUP`**（见上）—— 漏标**不会报错**，但会让下游只能用通用组件，
   而且**事后补不了**（到 Step 1 时 `_research/` 已删）。落盘那行打「关系覆盖：0 组」就是漏了。

**② 落盘 —— 一条命令出两份产物**：

```bash
python scripts/emit_facts.py --topic "<检索主题>" --mode full --sync-text assets/sources/_research/facts.txt --pages <总页数> --facade <门面数>
```

> `--pages` / `--facade` **缺省 = 15 / 7**（不传也能跑，体量预检就按 8 个内容页算 —— 传了才按真实页数算）。

| 产物 | 内容 |
|---|---|
| `assets/sources/_web_text_facts.json` | 溯源凭据（契约 §1.6）—— **带 URL**；`fact_id` 供 009 正文 `<!--FACTS: F001,F003-->` 引用 |
| `assets/sources/文本.md` 的**网络段** | `__来源网络 · <检索主题>__` ＋ **关系分组标题**（`### [G1] 构成 · <组标题>`，仅写了 `#GROUP` 时才有）＋ **逐条要点**（每条对应一条 fact）—— **不带 URL**；插入点恒在图片登记段**之前** |

**落盘注意事项**：

1. **脚本只「替换 / 插入」网络段，绝不重写整份 `文本.md`** —— **§0c 提纯后的本地段**、
   以及「## 附加图片」/「## 联网补充图片」登记段**原样保留**
   （`verify_extraction.py` 靠占位符计数，丢了直接 `exit 1`）。
   ⇒ **你不必自己拼 `文本.md`，也不用操心本地段与图片登记段**。
2. **脚本写完自己回读复验**（打印 `✅ … 合法` + 条数 + 带 URL 比例）—— 不必再手工检查。
3. **重跑必须带全量清单**（脚本对 json 与网络段都是**整份重写**，不做增量追加）——
   ⇒ **先修 `assets/sources/_research/facts.txt` 再重跑**，别直接改 `_web_text_facts.json`；
   **`#GROUP` 行也要一起带上**（整份重写 ⇒ 漏掉就等于关系标注全丢）。
4. 想**只校验不写** ⇒ `python scripts/emit_facts.py --check-only`。
5. **落盘后先打一行「事实密度」，再做体量预检** ——
   `→ 事实密度：30 条 · 平均 46 字符/条（claim 合计 1,385 字符）`。
   🔑 **平均字数明显偏低 = 「压得太狠」的当场信号**，不用等 WARN 就能看出来。
   随后做体量预检 —— 只有低于**放行线**才打
   `[WARN] 正文体量偏少：现有 N 字符 / 期望 M 字符（…% < 放行线 80% = K 字符）`。

#### ② 校验部分：验证提取输出

> **执行本部分不需要单独跑命令** —— 上面的 `check_step0.py` 已经包含它。
> 下面是「它做了什么」的说明；排错时可单独运行：
>
> ```bash
> python scripts/validators/verify_extraction.py --pages <PPT总页数> --facade <6 或 7>
> ```

**这是纯校验步骤，无副作用**（不下载、不改 `文本.md`）—— 补图归 §0f。

**校验分三态**：

| 状态 | 触发条件 | 行为 |
|---|---|---|
| **充足**（主分支） | 有图，且图量 ≥ 期望量 | 执行下方三项校验，通过，**无需补图** |
| **不足** | 有图，但图量 < 期望量 | 三项校验照做；**缺省 ON** → 额外提示执行 §0f 补图（`--count` 按缺口传）；**显式 OFF → 不补图**，Step 1 走无图版式 |
| **无图** | 一张图都没有 | 输出警告；**缺省 ON** → 提示执行 **§0f**；**显式 OFF → 不补图，直接继续**。**两种情形都 exit 0**（不算失败） |

> **图量算法**（`--pages` 传入 **PPT 总页数**时启用）：
>
> **期望图量 = 内容页数 × 2**，其中 **内容页数 = 总页数 − 门面页数**。
>
> 门面页数 = **`3 + 章节数`** = 001 封面 + 002 目录 + **N 张 003 章节过渡** + 010 致谢；
> 章节数只能是 3 或 4 → **门面页只能是 6 或 7**。
> **优先取 `--facade` 的传入值**（素材准备时 config 尚未生成，只能由你定好后传入）；
> 未传时才去 `pipeline_config.json` 数 003 过渡页张数；再没有则按 **7 页**兜底。
> （`--chapters 3|4` 是等价别名，两者都传时以 `--facade` 为准。）
>
> **不足即报警**（无容错系数）—— 图片进的是**备选池**，不一定全部用上，宁多勿少。
>
> | PPT 总页数 | 门面页 | 章节数 | 内容页 | 期望图量（备选池） |
> |---|---|---|---|---|
> | 12 页 | 7 | 4 章 | 5 | 10 张 |
> | 14 页 | **6** | 3 章 | 8 | 16 张 |
> | **15 页** | **6** | 3 章 | 9 | **18 张** |
> | **15 页** | **7** | 4 章 | 8 | **16 张** |
> | 20 页 | 7 | 4 章 | 13 | 26 张 |
>
> **门面页 = 「省图旋钮」**（总页数固定时 **6 → 7** 可让期望图量 **−2 张**；脚本会打印 `💡 调节旋钮` 行算好能省几张，已是 7 页则提示"没有更省的调法了"）。选法见本节开头的 `--facade` 说明。
>
> **为什么用 ×2 而不是拍脑袋的系数**：图片是**备选池**，进池的图未必要全部用上。
> 按内容页 ×2 备料，Step 1 规划骨架时才有足够余地让「图文左右 / 上图下文 / 夹心式」
> 这类吃图骨架自由摆布；否则会因图不够被迫全部退化成卡片页，观感单调。
> 旧逻辑 `内容页数 × 0.7 / 达成率 <60%` 会放过「9 页只有 5 张图」（算出 83% 假达标）。
>
> **开关 OFF 时，"期望图量"只作参考** —— 不足也**不补图**，Step 1 按实际图量规划
> （可用的编排余地会小一些，属**预期行为**，不是异常）。

#### 正文体量评估（①-c）

**图够了不代表料够了** —— 正文太薄，硬做只能「少讲」或「注水」；而且**报错要拖到 Step 1 才出现**
（卡在「内容量不足 / 净字数不够」，完全看不出根因是"料不够"）。所以在 0e 提前量一句。

```
📊 正文体量评估: 15 页 = 门面 7 + 内容页 8
   内容页 8 页 × 200 字符/页 → 期望正文 1,600 字符，现有 1,959 字符，达成率 122%
✅ 正文体量与目标页数相称（达成率 122% ≥ 放行线 80%）
```

**口径**：`期望正文 = 内容页数 × 200 字符`；**放行线 = 期望 × 80%**；
其中 **正文 = `文本.md` 去掉图片登记行后的净正文**。

> **200 字符/页 = 实测反推值**（「奥特曼」deck 净正文 1,959 ÷ 8 页 ≈ **245 字符/页**、成品 8 页全过 `check_creative_svg`）⇒ 本身自带余量。
> **放行线为什么是 80%**：下游内容页的**硬下限只有 140 字/页**（= 期望的 70%），按 100% 判「偏少」会把本来够用的素材误报、诱导回去反复补料；80% ⇒ 8 页 = 1,280 字符 = 160 字/页，仍高于硬下限 14%。
> 🔑 与 `emit_facts.py` 的 `BODY_WARN_RATIO` 同源（改一处必须改另一处）。

**不足时不阻断**（exit 0），只提示：

```
⚠️ 正文偏少（达成率 20% < 放行线 80% = 1,280 字符）—— 缺口约 960 字符
   ⇒ 这份素材撑不满目标页数，硬做只能「少讲」或「注水」（同属 sufficiency test 的缺口，不是失败）：
      转 §0d 定点补缺口补内容；或把页数往下调。
   （口径：正文 = 文本.md 去掉图片登记行后的净正文）
```

⇒ **转 §0d「定点补缺口」补内容**（见 §0d A 档），或**下调页数**。**别硬做。**

> **与 ① 清单那条「文本偏少」的区别**：① 用**全文字符数**、按固定的 15 页参考线；
> 这里用**净正文**、按**实际传入的页数**。定位不同（粗筛 vs 精确），**以这里为准**。

**三项检查**：

| 检查项 | 合格标准 |
|--------|---------|
| `文本.md` | 存在且内容不为空 |
| `image_*` | 图片数量 > 0 |
| `[[image_NNN.xxx]]` 占位符 | 数量与图片一致，格式正确（带后缀） |

**如果走到这里 `文本.md` 没有正文（空 / 只有图片登记行）→ 按下面的分支处理，不要直接进 Step 1**：

> **注意**：零素材 / 有缺口 / **只有图片**的情形**本该在 §0d 就消化掉** ——
> 走到 0e 这一步还没有正文，说明要么素材包读不出来，要么 §0d 也没取到实质内容。

| 情形 | 处理 |
|---|---|
| 输入文件**缺失 / 损坏** | 终止并说明「素材包无法读取」；可用 Word/WPS 打开确认内容存在 |
| **正文为空**（zip 里只有图片）—— `verify_extraction.py` 会打印 `⚠️ 正文: 仅 N 字符` | **不是失败** ⇒ 归入「**无文字素材**」⇒ **转 §0d 联网取材**补齐文字；**图片保留**作实拍配图（**优先于网图**）。细则见下方「只有图片怎么办」 |
| **零素材**、且 §0d 联网取材**也搜不到实质内容** | 终止并说明「该主题无法从公开信息获取」，请提供素材 |

#### 只有图片怎么办（「无文字素材」分支）

```

   ⇒ 与「零素材」同路：转 §0d 联网取材
      · 已有主题（提示词里写了）→ 直接用该主题检索
      · 没有主题 → 看图片内容 / 原始文件名推断主题

```

**为什么要放行而不是直接终止**：图片是调用方自己的素材（往往是现场实拍），**价值高于网图** ——
终止等于把这份素材白白作废。走 §0d 之后**图文各归其位**：文字来自公开资料（带来源标注），图片仍是实拍。

> **转 §0d 之后**：「## 附加图片」登记段**已由脚本自动保留**（`--sync-text` 只替换/插入网络段、不重写整份 `文本.md`，见 §0d D ②）——
> 按**旧写法**（模型从零写 `文本.md`）才会把它冲掉，复验直接报「**占位符 0 个 ≠ 图片 N 张**」（2026-10-08 实测）。

**但不能带着"没有正文"的素材进 Step 1** —— 内容页会无字可写，而且到那时报的是
「内容量不足 / 净字数不够」，**完全看不出根因**（2026-10-08 实测：只有 2 张图的 zip
被 `check_step0` 判为**全部通过**，一路带到 Step 1 才炸）。

**禁止**为了"把流程跑完"而改为凭主题自行编造内容 —— 那会产出一份**内容不可溯源、用户又看不出来**的成品。
**本 skill 的职责是"把资料组织成 PPT"，不是"替用户编资料"**（资料可来自素材，也可来自**带来源标注**的公开网络资料）。

### §0f：图量不足时的联网补图

> **前置闸门**：**缺省即执行**（2026-10-08 起缺省 ON）；
> 只有提示词**显式写** `[联网搜图：OFF]` 才**整步跳过**，直接继续 §0g / §0i（Step 1 走无图版式）。

**触发条件**（**前置闸门通过后**，满足任一即执行）：

| 触发场景 | 说明 |
|---|---|
| **0e 报「图片: 0 张」** | 素材里一张图都没有 —— **必须执行** |
| **0e 报「图量不足」** | 有图但少于期望量（见 §0e 图量算法）—— **应当执行**，按缺口张数补 |
| **智能体自行判断图不够** | 通读 `文本.md` 后发现可用于落实内容的图明显不够（如 15 页但只有 2 张可用图） |

> **何时可以不补**：图量已达标（≥ 内容页数 × 2）、或素材本身**提不出主题词**（如纯会议纪要）→ 跳过 0f，内容页走纯图形/表格布局。
> 阈值只是"提醒线"，不是"必须搜"——判断的最终依据仍是**这张图是否真的能服务于内容**。

#### 补多少张

按 **缺口 = 期望图量 − 现有图数** 传 `--count`（§0e 的提示里已算好并给出可直接复制的命令）。
图片进的是**备选池**（不必全部用上），所以缺口要按池子算足；但也别无脑多抓 —— 补过头只会让图片用不完，白白多占磁盘与来源标注。

#### 第一件事：智能体先定主题词（关键，别跳过）

> **别把提示词里的 `[PPT风格：xxx]` 当成搜索词** ——
> 那是**配色方案 id**（取值 = `assets/palettes/` 里的文件名；当前 `default` / `minimal` / `vibrant`），与本节要你定的「**主题词**」（补图关键词）**毫无关系**。
> 本节的主题词**必须从 `文本.md` 现读现定**，绝不能把配色 id 拿去当 `--keywords`。

**不要直接跑脚本让它自己提词。** 先由**执行本步骤的智能体**通读 `assets/sources/文本.md`，判断素材讲的是什么，给出 **3~5 组主题词**（多组用 `;` 分隔）：

> **下表右列的词全部只是「格式示意」，领域与本次素材无关。**
> **主题词必须从你手上这份 `文本.md` 现读现定 —— 素材是什么领域，就写什么领域的词。**
> **严禁**沿用示例里的领域（示例横跨多个领域正是为了提醒你：**没有"默认领域"**）。

#### 取词铁律：只给「具体实物」取词；抽象概念不取词、也不配图

> **先判这一页的性质**：它讲的是**看得见、拍得到的东西**（实物 / 设备 / 材料 / 工艺动作），
> 还是**抽象概念**（对标 / 生态 / 路线 / 战略 / 机制 / 方法论 / 架构 / 评估 / 认证）？
>
> - **抽象概念 → 根本不要为它搜图。** 这类词搜回来的只有**示意图与资质证书**
>   （实测 `软件质量评估证书` → **10 条里 9 条是证书**），而且证书上印着**别家公司名称**，
>   放到 PPT 上会被误读为自家资质。**这类页走无图骨架，不是缺陷**（契约 §1.7）。
> - **具体实物 → 才取词**，且必须遵守下面的公式与禁词表。

**禁词表（下列词一律不得出现在 `--keywords` 里）**

`评估` `认证` `证书` `报告` `规范` `指南` `原理` `方案` `如何` `一文看懂` `大全` `标准` `体系` `方法论` `架构`

**另一类同样要避开 ——「通用词」**（**本表是唯一权威版**；§0d 的文本检索**共用这一张**，不再另列）：

`分类` `系统` `构成` `施工` `工法` `应用` `技术` `发展` `建设` `管理` `概述` `意义` `现状` `措施` `要点`

→ 前一组把结果**系统性地导向文章与证书**，而不是现场实拍；
→ 后一组一旦被切出来会**主导全部结果**（§0d 文本检索实测：`综合管廊 分类` ⇒ 回来的全是
「**综合**」的词典页 +「CCTV-1 **综合**频道」+「4399 **综合**小游戏」）。
→ 两组都**只加污染、零收益**；**搜不到就「换词」，不是「加词」**。

**取词规则全文只有一份**：**§0d 的查询词**与**本步的 `--keywords`** 是同一套规则 ——
两边都**只给专有实体**、两边都**不许混通用词**（同一机制：加词 → 该词被单独切出 → 反客为主）。
差别只在**用途**：查询词找**网页正文**，`--keywords` 找**实拍图**。

**取词公式：`具体对象 + 动作 / 场景`**（前面可再加**项目实名或地域**，提升语域）

| 反面（泛词 / 抽象词） | 正面（对象 + 动作 + 实名） |
|---|---|
| `LNG 储罐` | `营口 LNG 接收站 储罐 施工` |
| `储罐` | `储罐 外罐 焊接 现场` |
| `脚手架` | `脚手架 搭设 施工现场` |
| `仪表` | `仪表 变送器 安装` |

> **为什么必须带「动作 / 场景 + 实名」**：同一个对象 —— 泛词 `LNG 储罐` 拿回的是
> 「怎么选 / 一文看懂 / 操作规程」类文章的**示意图**；而 `营口 LNG 接收站` 拿回的 12 条
> 几乎全是**新闻媒体实拍**（含"本报记者摄"）。**取词的语域，直接决定拿回的是实拍还是文章配图。**

| 判断什么 | 例子（**仅为格式示意，勿照抄领域**） |
|---|---|
| 素材讲哪个领域 / 对象 | `新能源汽车 电池 产线` |
| 素材里的**通用知识**部分是什么 | `消防安全 规范 培训` |
| 素材里有哪些**专业培训**板块 | `财务报表 分析` · `合同法 要点` |
| 素材里有哪些**设备 / 工艺** | `光伏 组件 安装` · `污水处理 工艺` |
| 提不出主题（如纯会议纪要） | **不要搜** → 跳过 0f，内容页走纯图形/表格布局 |

> **为什么要 3~5 组，而不是抠一个词**：一组词只能覆盖素材的一个侧面，搜回来的图高度同质。
> 素材通常横跨「现场实操 / 专业培训 / 通用原理」几个板块 —— **按板块各给一组**，
> 图库才有多样性，Step 1 分配时也才有的挑。
> 组数越多覆盖面越广；`--count` 是**总**张数，脚本会在组间自动均分。

> **为什么必须智能体来定**：脚本的兜底提取是「词表 + 后缀特征」匹配，对**无主题文本**必然产出垃圾词（曾实测得到 `LNG 接收站 备注 第一条 第二条`）。语义理解只有模型能做。
> 换更好的分词器也解决不了 —— 因为问题不是"分词不准"，而是"这段文字本身没有主题"。

#### 命令

```bash
cd <SKILL_ROOT>

# 【主路径】智能体定好主题词后传入（推荐）—— 多组用 ; 分隔
# ⚠️ 下面的词只是占位，换成你从 文本.md 读出来的真实主题
python scripts/fetch_web_images.py --keywords "领域词 对象词;通用知识 词;设备 工艺 词" --count 12

# 只给一组也可以
python scripts/fetch_web_images.py --keywords "素材主题 关键词" --count 8

# 【兜底】智能体确实给不出主题词时才用；提不出会自动放弃补图，不硬搜
python scripts/fetch_web_images.py --count 12
```

`/workspace/_state/photo_plan.json` 是照片落页的权威记录。不要手写这份 JSON。每张图只属于一页，每一页最多一张图。

**参数**：

| 参数 | 说明 | 默认 |
|---|---|---|
| `--keywords "词A 词B;词C 词D"` | 搜索主题词，**多组用 `;` / `\|` / `；` 分隔**（**主路径**） | 缺省则脚本兜底提取（只能出 1 组） |
| `--count N` | 下载**总**张数 —— 多组时自动均分，某组不够的余量**顺延给下一组** | 12（上限 24） |
| `--min-width N` | 实际宽度下限（px） | 580 |
| `--force` | 该主题**已抓过**时仍强制重抓 | 不传则跳过（见下方约束 #4）。**「已抓过」的判定是「抓到 ≥1 张」，不是「搜过」** —— 0 张 / 搜索失败的组会自动重试，无需 `--force` |

#### 脚本内部做什么

1. 先访问 `image.baidu.com` 首页取 Cookie —— **不带 Cookie 直接请求接口会被拒**（`{"antiFlag":1,"message":"Forbid spider access"}`）
2. 按 `;` 把 `--keywords` 拆成 N 组，**逐组**请求 `acjson` 接口拿候选（`rn≥30`）
3. 过滤 + **语域排序** + **同源去重**：只留**横向图**（`width > height`）→ 卡宽度 → 按「**语域分 → 清晰度 → 宽度**」排序（**现场实拍优先**，证书 / 文章配图排最后）→ 同标题 / 同目录的裁剪版本**只留代表**
4. 下载 + 校验（Content-Type / 体积 / Pillow 可打开）+ **文档闸**：**近白底 + 极低饱和**的扫描件 / 证书类图**直接剔除**（剔除后**不补位**）
5. 组间均分 `--count`；某组搜不到或没抓够，余量**顺延给下一组**
6. 编号落 `sources/image_NNN.ext`（**接续现有最大编号**，不与已有图冲突）
7. 在 `文本.md` 文末 `## 联网补充图片` 段登记（每张一行，各自带 `主题：`）
8. 落 `sources/_web_images.json` 审计清单（含完整来源 URL）；`keywords` 按「主题 → **实际得图数**」记账（0 张也记，供下次重试判定）

> **某组颗粒无收**（接口返回空 / 搜索失败 / 宽度全不达标）⇒ 该组**记为 0 张**、打印 `↻ 上次 0 张（未获图），本次自动重试`，余量顺延给下一组；
> **下次同主题会自动重试，不会被当成「已抓过」跳过**。只有已抓到图的组才打印 `⊘ 已抓过（N 张），跳过`。

**登记格式**（与散图结构统一，**下例的标题/来源仅示意**）：

```markdown

[[image_001.jpg]]（网图 | 主题：<实际主题词> | 标题：<搜索结果里的原始标题> | 来源：<域名> | URL：<完整地址> | 尺寸：750×500）

#### 五条硬约束

| # | 约束 | 说明 |
|---|---|---|
| 1 | **宁缺毋滥** | 兜底提不出主题词 → **放弃补图**，不硬搜。搜不到合适图**不阻断流程**（exit 0） |
| 2 | **够用即止** | 按 §0e 算出的**缺口张数**补，不盲目多抓。图量达标（≥ 内容页数 × 2）就不必补 |
| 3 | **版权留痕** | 登记行保留 `来源` + `URL`；`_web_images.json` 存完整审计字段。若 PPT 实际用了网图，该页最下方须加来源标注（规格见 `creative_contract.md` §1.6）。百度偶有不返回原始来源 URL → 脚本**自动回退 CDN 地址并标 `（CDN 回退）`**，不留空段 |
| 4 | **不重复抓** | 脚本启动时检查 `_web_images.json` 的 `keywords`（格式 `{主题: 得图数}`）：**逐组判定** —— **抓到 ≥1 张**的组才跳过（打印 `⊘ 已抓过（N 张）`），**得 0 张的组自动重试**（打印 `↻ 上次 0 张…本次自动重试`），其余组照常处理；**全部**都抓到过才整体跳过（exit 0）。确需重抓加 `--force`。判定依据是**「抓到几张」而非「搜过没有」** —— 旧版按「搜过即记账」写，某次接口返回 0 条该主题就被记成「已完成」，**永远补不上**（除非想到加 `--force`）。旧版 list 格式的清单会被**自动迁移**：用 `文本.md` 登记段反推每个主题的真实张数，无需手工处理 |
| 5 | **抽象页禁配图** | **抽象概念页（对标 / 生态 / 路线 / 战略 / 机制 / 方法论 / 架构 / 评估 / 认证…）压根不要取词、不要配图** → 走无图骨架（契约 §1.7）。这类词搜回来只有示意图与证书，**证书上还印着别家公司名** ⇒ 不是"不相关"而是**误导**。**"搜不到"和"不该搜"是两回事** —— 别把"没搜到"当成失败去反复换词 |

> **本步只在开关 ON 时执行**；唯一附加要求：**用到网图的页必须加来源标注**（§1.6，由 Step 2f 自动注入）——这是版权留痕、与用途无关。
> （「抽象概念页禁配图」见上方硬约束 **#5**，此处不重复。）

**失败处理**：

| 症状 | 原因 | 处理 |
|---|---|---|
| 某组 `接口 30 条 → 横向 0` | 该组关键词太冷门 | 只换掉那一组重跑（已抓过的组会自动 `⊘` 跳过）；仍不行则放弃该组 |
| 某组 `接口 0 条 → 横向 0` | **搜索接口返回空**（接口抽风 / 关键词极冷门） | 该组记为 **0 张**，余量顺延给下一组；**下次同主题会自动重试**，不必手工干预。同一串词上轮能搜到、这轮归零，多半是接口侧问题 |
| 某组抓到的张数不够 | 该主题图源少 / 小图多 | **正常** —— 余量自动顺延给下一组；整体仍不够就再补搜新主题 |
| 全部 `[跳过] 实际宽度不足` | 该主题图普遍偏小 | 降 `--min-width 500` 重试，或换关键词 |
| `[跳过] 疑似文档/证书类图，已剔除` | 搜到的是扫描件 / 证书（近白底 + 极低饱和） | **正常** —— 脚本已自动剔除、**不补位**。若**整组**都命中此提示，多半是**这组词取错了**（用了抽象概念词）→ 换「对象 + 动作」词重试；该页若本就是抽象概念页 → **改走无图骨架**，不要再搜 |
| `⚠️ 搜索失败: ...` | 网络 / 接口异常 | **不阻断**（exit 0）；该组记为 0 张 → 下次同主题自动重试，临时异常无需手工处理 |
| `兜底提取未得到主题词` | 文本缺少领域特征词 | **正常行为** —— 直接放弃补图（说明素材本就无主题） |
| `❌ 既无 --keywords，又无 文本.md` | 顺序错了 | 先跑完 0a / 0b 再执行本节 |

> **补图完成后回 §0e 复跑一次** `check_step0.py`（同样带 `--pages --facade`；或单独跑其中的 `verify_extraction.py`）确认图量已达标 ——
> 补图的目标是"够用即止"，不复验就不知道够没够。达标后继续 §0g。

### §0g（🔖 参考）：图片占位符约定

> 🔖 **本节是参考章节，不在执行序列里**（顺序见开头「执行顺序总表」）—— 写 `design_spec.md` 前读一遍即可。

`文本.md` 中 `[[image_NNN.jpeg]]` 与 `assets/sources/image_NNN.jpeg` 一一对应。后续写 `design_spec.md` 时：
- **§VIII** 中通过占位符编号定位图片（`[[image_NNN.xxx]]` → `sources/image_NNN.xxx`）
- **§IX** 中引用图片编号分配页面
- 🔴 **选图依据是登记行里的「内容：」字段** —— **§0c ②（本地素材：内嵌图据原文图注、散图才看图）/ §0f（联网网图：据搜索主题与标题）** 都会给出一句语义说明 ⇒ **Step 1 读登记行即可，不必自己开图**。
  ⚠️ **没有「内容：」= 没走过 §0c ②**（旧素材 / 未提纯的图）；那时唯一线索只剩「目录 + 文件名」，
  含混名（`IMG_20260830_113245.jpg`）就会选不准 —— 这正是 §0c ② 要补的缺口。

#### 三类图片的上下文形态（本地素材经 §0c 后**统一带「内容：」**）

**文档内嵌图** —— 原位置在图注旁；**经 §0c ② 后统一收进文末登记段**，原图注并进「内容：」：

```markdown
[[image_001.jpeg]]（内嵌图 | 内容：脚手架拆除现场）
```

**zip 散图** —— 本来就没位置关系（统一登记在文末 `## 附加图片` 段），§0c ② 在其后**追加**「内容：」：

```markdown
## 附加图片

[[image_001.jpeg]]（内嵌图 | 内容：脚手架拆除现场）
[[image_006.jpg]]（散图 | 目录：/ | 文件名：IMG_20260830_113245.jpg | 内容：罐顶阀门检查）
[[image_007.jpg]]（散图 | 目录：照片/子目录A | 文件名：场景A.jpg | 内容：储罐外罐焊接）
[[image_009.jpg]]（散图 | 包：补充材料.zip | 目录：照片 | 文件名：场景C.jpg | 内容：管廊支架安装）
```

登记行按「包 / 目录 / 文件名 / 内容」拆分：
- **包** —— 仅嵌套 zip 里的图才有，标明它来自哪个子包
- **目录** —— zip 内的原始目录路径（**原始事实，不改**）
- **文件名** —— 原始文件名（**原始事实，不改**）
- **内容** —— **§0c ② 写的语义说明**（内嵌图**据原文图注**、散图看图；`内嵌图` 那行没有目录/文件名，只有内容）

> ⚠️ 「内容：」是**新增字段**，**不动原有三段** —— `check_materials.py` 靠「散图 / 内嵌图 / 网图」
> 这些词分类，别改它们；`verify_extraction.body_only()` 靠**行首** `[[image_…]]` 整行剥除
> （加了「内容：」仍能正确剥掉，不会计进正文体量）。

**联网网图** —— 来自 §0f 补图，**不是实拍**，统一登记在文末 `## 联网补充图片` 段：

```markdown
## 联网补充图片

[[image_015.jpg]]（网图 | 主题：<实际主题词> | 标题：<搜索结果原始标题> | 来源：<域名> | URL：https://... | 尺寸：750×500）
```

- **主题** = 实际使用的搜索关键词（天然的语义标签）
- **标题** = 原图所在的网页标题（说明图的内容）
- **来源 / URL** = 出处站点与原始链接（**版权留痕**）
- **「网图」这个标记决定 Step 2f 要不要加来源标注** —— 用到网图的页会自动补一行出处（契约 §1.6），**与用途无关**

> 三类图片的语义线索：**本地图**（`内容：` 语义说明 —— 内嵌图据图注、散图看图，最准）＝ **联网网图**（搜索主题 + 标题，较准）——
> 两者都**不必打开图片**即可选图；**唯独**没走过 §0c ② 的旧素材只剩「目录 + 文件名」。

#### 用户描述补注（手动，非脚本）

若调用方在**对话中口头说明**了某张图的内容（如「那张阀门图是罐顶的」），**必须把它补注进 `文本.md` 对应登记行**，避免信息只留在对话上下文里、跨会话丢失。

**补注格式** —— 在登记行括号内追加 `| 用户说明：<描述>`：

```markdown
[[image_006.jpg]]（散图 | 目录：/ | 文件名：IMG_001.jpg | 用户说明：罐顶阀门检查时拍摄）
```

**规则**：
- 只追加 `用户说明：` 段，**不改动**原有的「包 / 目录 / 文件名 / 内容」段 —— 它们是原始/脚本事实，
  `用户说明：` 才是补充。（§0c ② 的 `内容：` 是**据图注 / 看图写的**、`用户说明：` 是**调用方口头说的**，
  两者语义不同、可并存，如 `… | 内容：阀门 | 用户说明：罐顶那台，已停用`。）
- 用编辑工具直接改 `assets/sources/文本.md`，**不需要重跑 `extract_all.py`**（重跑会清空 sources 并覆盖）。
- 时机不限：素材准备跑完后的任何时刻都可补，但**必须在 Step 1 编写 `design_spec.md` 之前完成**。
- 若同一张图有多条描述，合并为一句写入（用「；」分隔），不新增 `用户说明` 段。

### §0h（🔖 参考）：失败处理

> 🔖 **本节是参考章节，不在执行序列里** —— 出问题才回来查。

| 症状 | 原因 | 处理 |
|------|------|------|
| **无素材 + 无主题**（连一句主题都没有） | 调用方只说"帮我做个 PPT"，既没上传文件、也没说主题 | **终止并说明**「请提供素材，或指明主题」。**不要**自己编一个主题去联网搜 —— 那是边界 1 的红线。判定见开头「执行顺序总表」 |
| **素材与主题明显不相干** | 说 A 却给了 B（传错文件 / 打包错目录） | **终止并说明**「素材内容与主题不符，请确认是否传错文件」。判据：**素材一半以上板块都对不上主题**；只有一两块没覆盖是"缺口"（走 §0d 补），不是不相干 |
| `verify_extraction.py` 报「正文偏少」 | 有正文，但**不到期望的 80%**（净正文 < 内容页 × 200 × 0.8 字符） | **不是故障**：转 **§0d 定点补缺口**补内容；或把页数往下调（§0e 重传 `--pages`）。别硬做 —— 到 Step 1 会卡在「内容量不足」，看不出根因。⚠️ **达到 80% 就不算「偏少」**，别为最后 20% 反复补料 |
| `extract_all.py` 打印 `❌ 未找到任何支持的素材类型`（exit 1） | **给了 zip，但里面一条素材都没有**（空包） | **这不是故障，是「零素材」分支** ⇒ 跳到 **§0d 联网取材**（不必终止）。**取材后仍拿不到实质内容才终止**（见下一条）。另注：**完全没给 zip 时根本不要跑 `extract_all.py`**（会报 usage error）—— 判定见开头「执行顺序总表」，零素材直接进 §0d |
| §0d 联网取材**搜不到实质相关内容** | 主题太冷门 / 属**私域**（如"我们公司 Q3 进展"） | **终止并说明**「该主题无法从公开信息获取，请提供素材」。**禁止**拿无关内容凑数、也禁止凭主题编造 |
| `verify_extraction.py` 报「本地段（`__来源本地 ·`）没有任何 `### [Ln]` 标注」 | **§0c ① 漏标** —— `_local_facts.txt` 没写 `#GROUP` 行 | **不是故障**：回 §0c 给清单补 `#GROUP Ln \| <关系> \| <块名>`、重跑 ③。**不补的代价**：下游退回默认「并列」，R1 / R3 / R6 / L1~L3 触发不了（不报错，只是成品骨架雷同） |
| `emit_facts.py --local` 报 `--local 必须与 --sync-text 同用` | 命令忘带 `--sync-text` | 本地模式的产物就是 `文本.md` 的**本地段** ⇒ 补上 `--sync-text` 重跑 |
| `emit_facts.py` 报 `第 N 行：\`#GROUP\` 字段不足 / 关系不在枚举内` | 清单里的 `#GROUP` 写错 | 按提示改**清单**再重跑（关系只能取 并列/构成/对比/递进/时序/分层）；**别手改 `文本.md`** —— 那是「下游改上游」 |
| §0c ③ 落盘后 `[[image_NNN]]` 数 ≠ 图片数 | **② 没把图全部挪进 `## 附加图片`**（正文里还留着占位符），③ 替换正文区时把它们一并带走了 | **fail loud**：把漏掉的图补进 `## 附加图片` 登记段（带「内容：」），重跑 ③ |
| §0c 后体量比提纯前**明显变小** | **正常** —— 提纯就是把原文压成要点；真实体量以 §0c ④ 量为准 | 不够就去 §0d 定点补缺口；**不要**为了"数字好看"把要点写虚 |
| `extract_all.py` 打印 `❌ 输入文件不存在: xxx` | zip 路径写错 | 检查传入的绝对路径 |
| `extract_all.py` 打印 `❌ 输入必须是 .zip 文件` | 传入的不是 zip | 确认后端打包正确 |
| **Phase 2.5 预检失败**（打印 `❌ 素材里有文件需要以下依赖…`） | 环境缺该格式所需的 Python 依赖 | 依赖还没装就开跑。按提示里给出的命令安装（如 `pip install PyMuPDF openpyxl`），装完**重跑 §0a → §0b** |
| 打印 `⚠ 转换失败: ...` 后 continue | **最常见：缺对应格式的依赖** —— pdf 需 `PyMuPDF`(fitz)、xlsx 需 `openpyxl`、html/网页需 `beautifulsoup4`+`markdownify` | 先自查：`python -c "import fitz, openpyxl"`。缺则装上再重跑（**重跑前必须先执行 §0a 清空 `sources/`**，否则新旧照片会混在一起） |
| 打印 `⚠ 该文档产出 N 张图，其中 M 张未被正文引用、未收编` | 源文档里有"存进了 media 目录、但正文没有引用"的图（页眉图 / 文本框里的图） | **是提示不是报错**（脚本 exit 仍为 0）：这些图不会进入 `sources/`，随后随临时目录删除。若确实需要它们，请在源文档中把图放进正文再重跑 |
| 打印 `⚠ 正文有 N 处图片引用，但只找到 M 个图片文件` | 引用路径解析失败（相对路径的图丢失 / 网页图抓取失败） | 检查源文档里的图片能否正常打开；缺图不阻断流程，但该处内容会少图 |
| 同上（`⚠ 转换失败`） | 其次：该篇文档**损坏或非标准格式** | 用 Word/WPS 打开该文件 **另存一次**再重跑；若该篇内容本就不需要，可忽略 |
| `verify_extraction.py` 报 `⚠️ 正文: 仅 N 字符（其余都是图片登记行）` | **zip 里只有图片、没有文字** | **不是故障**：归入「无文字素材」⇒ 转 **§0d 联网取材**（图片保留作实拍配图，优先于网图）；有主题就用主题、没主题就看图推断，推不出才终止 |
| `verify_extraction.py` 报「图片: 0 张」 | 源素材里确实没有图片 | **缺省即联网**（2026-10-08 起）⇒ 执行 §0f 联网补图（先通读文本定主题词）；提不出主题或搜不到则跳过。**仅当提示词显式写 `[联网搜图：OFF]`** 才不补图，Step 1 直接走无图版式 |
| `verify_extraction.py` 报「图量不足」 | 有图但少于期望量（内容页 × 2） | **缺省 ON** → 执行 §0f 按缺口补图（提示里已给出 `--count <缺口>`）。**显式 OFF → 不补图**，按现有图量规划即可 |
| 0f 报「兜底提取未得到主题词」 | 素材文本无领域特征词 | **正常** —— 放弃补图；**正确做法是用 `--keywords` 由智能体指定主题** |
| 0f 报「接口 30 条 → 横向 0」 | 关键词太冷门 | 换更通用主题词重跑；仍不行则放弃补图 |
| 提取出的照片是**模板占位图**而非现场照 | 源文档里混了模板页/示意图 | 人工在 `assets/sources/` 里删掉对应 `image_*.jpeg`；Step 1b 数照片以清理后为准 |
| 占位符数量与图片数不匹配 | 个别图片未被 `![...](...)` 语法引用 / §0c ② 移图漏了一张 | 人工核对 `文本.md`，把缺的补进 `## 附加图片` 登记段（带「内容：」）；**别在正文里另放一份**（重复会让计数变 2N ≠ N） |
| docx **加密 / 需要密码**，mammoth 读不出内容 | 源文件受保护 | 跳过该文件并在输出中记录；若必须处理，需调用方先提供去密码版本 |
| 提取的文本**乱码** | 源文件编码异常 | 用 Word/WPS 打开该文件 **另存一次**（统一编码）再重跑 |
| zip 内嵌套 zip 同名覆盖 | 多层级有同名文件 | 脚本已处理：扁平化时加路径前缀（`subdir_report.docx`） |
