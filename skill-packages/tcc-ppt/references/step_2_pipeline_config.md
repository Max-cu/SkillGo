> **输入**：`assets/design_spec.md`（重点 §VIII 图片清单、§IX 页面蓝图）

### Step 2b：搭建 JSON 骨架

**操作**：先写出 JSON 的外壳结构，不要急于填内容。

> ⚠️ **Step 1a-0 已落过一个只含 `_meta.palette` 的外壳**（供 `check_design_spec.py` 认出风格）。
> 本步**整个重写该文件**（**覆盖，不是追加**）：把 `_meta` 补全（`project` / `author`），并追加 `pages`。

```json
{
  "_meta": {
    "project": "<从 design_spec.md §I 提取的项目名>",
    "author": "<作者姓名>",
    "palette": "<配色方案 id>",
    "template_set": "<门面页风格名>"
  },
  "pages": []
}
```

- `_meta.project`：与 design_spec.md §I `Project Name` 一致（**其本身 = 封面 `TITLE`** —— 素材有现成标题就用原题，没有则据内容拟题，规则见 `step_1` §1e）。
- `_meta.author`：**只能来自素材**。取值优先级（**依次尝试，取到即止**）：
  1. `.docx` / `.doc` 等**素材文件名**里的作者（如 `实习记录2026.08.29-张三.docx` → `张三`）
  2. `文本.md` **正文里明确写出的**作者 / 汇报人姓名（如落款、署名前缀）
  3. 都取不到 → **一律填占位语 `TCC`**（全大写 ASCII ⇒ 英文字体自动落 Arial；提示调用方补填；不要写 `未署名`）

  **硬禁止**：素材里没有署名时，**绝对不许凭记忆、上下文或"典型人名"自行编造**，
  更**不许填 skill 作者或任何与你有关的人名**。本 skill 是通用工具，**它自己的作者与用户素材毫无关系**——
  把 skill 作者名写进别人的成品里，是**严重的越界**。
  **正确做法**：填 `TCC`，并在 Step 2h 收尾时**明确告知调用方**：
  「素材未提供作者姓名，`_meta.author` 已填占位语 `TCC`；如需署名请补充后重跑 Step 2b/2e/5。」
- `_meta.palette`：**配色方案 id**，取自 **前置解析的 `[PPT风格：xxx]`**。**取值 = `assets/palettes/` 下的方案文件名（不含 `.json`）** —— 🔴 **以目录实际内容为准，别记死名单**：目前是 `default`（商务风）/ `minimal`（简约风）/ `vibrant`（活力风）三个，**加新方案时这里不用改文档**；标记缺失 / 解析不到 / 为其它值 → **一律填 `default`**（**别把无效值原样落进 config** —— 那会让数据与实际行为不一致）。
  该字段由 `build_svgs.py` 的 `resolve_palette()` 自动读取；**不写 ⇒ 等同 `default`**。
  **它只作用于创作页（009）** —— 门面页（001/002/003/010）**永远原样输出**（`build_svgs.py` 已在代码里限定：只对 `009_content.svg` 调 `apply_mapping`）。
  **为什么**：门面页风格本质是**整张版式设计**（底图 + 光效 + 构图），观感主色来自**照片**，改矢量色值改变不了整体风格 ⇒ 换门面页风格请改 `_meta.template_set`，**不是**这个字段。
- `_meta.template_set`：**门面页风格名**（2026-10-09）—— 选 `assets/templates/` 下哪个**子目录**当门面页来源。
  - **一般情况：不写它**（方案 C-1，用户拍板）。省略后脚本**从 `palette` 派生同名目录**，且两者**原子切换 —— 要么都换、要么都不换**：
    - `templates/<palette 值>/` **存在** ⇒ 整套用它（**选 minimal = 门面页 + 009 一起变墨绿**）。
    - **不存在** ⇒ **配色也一并回退 `default`**（打印一行说明、**不中断**）⇒ 成品是**完整的 default 稿件**，**不会出现「蓝封面 + 橙正文」的半成品混搭**。
    - ⇒ **同一句提示词，在 `templates/minimal/` 建好前后自动切换行为**，无需改 config / 提示词。
  - **只在一处显式写它**：刻意混搭「某门面风格 + 另一套配色」（如「科技风门面 + minimal 配色」）。此时写上风格目录名，**优先级最高**且**不做原子回退**、配色照常生效。
    **显式写的值必须真实存在**；不存在 ⇒ `build_svgs.py` **报错退出**（列出可用风格），**不像 palette 那样回退** —— 那是**写错了**，静默降级会悄悄出一份错误风格的稿。
  - **它同时决定去哪读占位符定义与容量表**：`assets/templates/<风格名>/` 下的 `pipeline_config.schema.json` 与 `template_capacity.md`（**按风格各一份**）⇒ 填 `text` 前先按解析出的风格找到对应目录。
  - **与 `palette` 正交可组合**、**缺省时自动同步**（同名派生）；**别把配色 id 当风格目录名去"猜"路径**。
- `_meta` 是固定结构，`export_flat.py` **只用 `_meta.project`** 拼出最终 `.pptx` 文件名（`YYYYMMDD_<项目名>.pptx`，**不含作者名**；**非法字符自动清洗**、**同名自动另存 `-02`**），不需要另外写 `output_filename`。

### Step 2c：逐页翻译 §IX → JSON page 对象（门面页）

按 design_spec.md §IX 的页面顺序，从 page01 到最后一页，逐页执行。**先判断该页模板类型**：

- 模板是 `001/002/003/010`（门面页）→ 走本步骤（2c，占位符填充）
- 模板是 `009`（创作页）→ 跳到 **Step 2c-2**（创作页分支）

#### 对每一页（门面页）：

1. **写 `id`**：与 §IX 的 `pageXX` 一致，如 `"page01"`。
2. **写 `page`**：与 `id` 的数字部分一致，如 `1`。
3. **写 `template`**：**必须带 `.svg` 后缀**，如 `"009_content.svg"`（不是 `"009_content"`）。可用模板：`001_cover.svg` / `002_toc.svg`（4 章目录）/ `002_toc_3ch.svg`（3 章目录）/ `003_toc.svg` / `009_content.svg` / `010_ending.svg`。
4. **写 `output`**：格式 slide_NN_&lt;slug&gt;.svg：
   - `NN`：两位数页码（`01`~`20`），与 `page` 数字一致。
   - &lt;slug&gt;：简短英文描述，小写+下划线，5~20 字符。从页面主题提炼。
   - 示例：`slide_04_xxx_yyy.svg`（`xxx_yyy` 换成该页真实主题）
   - **禁止**：中文文件名、空格、大写字母。
5. **写 `text`**：将 §IX 该页的占位符映射表逐行翻译为 JSON 对象：
   - **字符串值** → 直接写 `"KEY": "值"`，如 `"PAGE_TITLE": "页面标题"`（**值取自 blueprint，不是下面这个例子**）
   - **无文本占位符的模板**（010_ending） → 写空对象 `{}`

### Step 2c-2：009 创作页 —— 写正文 SVG 片段 + 登记 JSON

对每个标注为 `009_creative` 的页面，**先写正文片段、再登记 JSON**。§IX 里的 `009_creative` 对应 JSON 的 `template = "009_content.svg"`。

#### 第一步：写正文 SVG 片段

> 🔴🔴 **动笔前先读该页「图形元素」列里的 `（框 <A~F> · 内容 <1~5>）`** —— 这两项**决定怎么画**，不是备注。
>
> **框号 → 外框画法**（②册 C1「外框 6 款」，**逐款不同，不能混**）：
>
> | 框 | 画什么 | 关键尺寸 |
> |---|---|---|
> | **A** | 左侧**通高**实心色条 ＋ 浅底 ＋ 描边 | 色条 `5 × h` |
> | **B** | 顶部一段**短**实心条 | `56 × 6`，⚠️ **不是整格宽** |
> | **C** | 底部一条**短**实心线 | `80 × 2`，⚠️ **别拉成通宽** |
> | **D** | 左竖 ＋ 顶横的 L（**一条 `<path>`**） | `stroke-width 2.5`，`fill="none"` |
> | **E** | 四角各一个直角（**四条 `<path>`**） | 每个 `10 × 10`，`stroke-width 1.5` |
> | **F** | 顶部**通宽**线 | `w × 2` |
>
> **内容款 → 字怎么摆**（②册 C1「内容 5 款」）：`1` 上下式 ／ `2` 词条式 ／ `3` 引领句 ／ `4` 分条式 ／ `5` 数字式。
> 坐标见 ②册 C1「内容 5 款」表（标题 `x+12, y+34` 之类），**A 款时所有 `x+12` 改 `x+24`**。
>
> ⛔ **框号只写在蓝图上、SVG 里没照它画 = 白写。** 2026-10-17 实测：蓝图写了 `框 A~F` 六种轮换，
> Step 2 却自己另轮了一套 —— **写 A 的画成四角标、写 E 的画成顶部标头、写 F 的什么都没画**，
> 用户翻页看到的仍是"全都一个样"。**蓝图写哪款，就必须画哪款。**

> **动笔前先确保 `assets/svg_body/` 存在** —— `reset_project.py` 会**整个删掉**这个目录，
> 所以**干净安装 / 重置后必然没有它**，直接写文件会失败。不存在就先创建：
> `python -c "import os; os.makedirs('assets/svg_body', exist_ok=True)"`（`python` 不可用则换 `python3`）

1. **读蓝图**：回到 design_spec.md §IX 该页的「创作蓝图」（布局形态 + 区块内容 + 配图 + 字数预算）。
2. **按契约写 SVG**：严格对照**契约三册**写正文片段（**②** §4.8 组件库、**③** §5 版式家族坐标、**①** 合规红线与六条铁律）。

   **反向禁止**：**契约三册**是校验规则的**唯一权威**，`check_creative_svg.py` 只是它的机器实现、两者严格一致。写 SVG 只需对照契约，**不要读** `check_creative_svg.py`、`svg_authoring_contract.py`、`compact_svg_styles.py` 等校验器源码——读它们不增加正确性、只会拖慢；校验靠直接**运行**脚本（见第二步），不要读实现。
   - 🔴 **配色只写「母色表」，不写「出片色」**：正文 SVG 里**所有** `fill` / `stroke` 一律写
     **契约 §1.3 的公司 8 色**（`#003C96` / `#C11920` / `#307FE2` / `#013B94` / `#FFD806` /
     `#FFFFFF` / `#262626` / `#404040`）。
     **不要写 `palettes/<id>.json` 里的调色板色**（如 `minimal` 的 `#2F4A42`）——
     那是 `design_spec.md` §III 记的**「出片色」**（它只描述本次成片观感），
     Step 3 会拿它**整表替换**掉母色表；在正文里直接写它 ⇒ 会被判「配色违规」并返工。
   - **优先复用 §4.8 的 24 类组件**（C1~C10 承载型 / R1~R6 表达型 / G1~G5 通用型 / L1~L3 整页型）。承载型：C1 要点卡（6 框 × 5 内容） / C2 实心数据块 / C3 提示条 / C4 压图图注 /
     C5 流程链 / C6 细线分隔 / G 2×2 矩阵 / C8 等级徽章 / C9 斑马纹表格 / **C10 编号条目行**），不要每页都从零画白底矩形。
     > **用到 §5.10 编号条目列骨架时**：它由**组件 C10** 撑起。**独占一页必须按 §5.10.1「实体化」写**
     > （给每条补 1200×114 浅底 + 左色条，序号圆改 `cx=88`、标题/正文改 `x=128`）——
     > 否则纯组件 C10 无浅底，填充率会被算成 **0% < 25%** 被 §2.4 拦下。
   - **同色铁律**：用组件 C1 的 A 款（左色条）这类"三件套"时，**色条 / 浅底 / 标题色必须同一个颜色**——
     红条配蓝底是最常见的错（组件 C1 示例早已改成红条红底，别照抄旧印象），见 §2.3 同色铁律。
   - **相邻页不得同骨架**；**底部通栏条全篇 ≤1/3**（不写也行——最底部元素底边对齐 `y=648` 即可）。
   - **不要画标题/页头**；正文第一个元素从 `y=104` 起。
   - **只写正文部分**，不写 &lt;svg&gt; 根标签、不写页头/logo/页脚（那些由 009 头部模板在 Step 3 拼接）。
   - 最外层用 &lt;g font-family="黑体, Arial, sans-serif"&gt;...&lt;/g&gt; 包裹。
   - 照片直接写真实路径：&lt;image href="../sources/image_NNN.jpeg" ... /&gt;（照片已在 §VIII 登记，文件名用实际文件）。

   #### 图标（**默认执行**；**只有** §VI 明确填了 `None` 时才跳过）

   1. **先定库，再搜名字** ——**别因为下面示例写的是 `tabler-outline` 就默认用它**
      （示例用它只是排版方便，不代表默认值）。按这三问重新定一次，并写进 `design_spec.md` §VI 的 `Library`：

      | 库 | 数量 | 风格 | 何时选 |
      |---|---|---|---|
      | `tabler-outline` | 5,138 | 细线描边 | 浅底 + 细线 + 小字的**商务/技术风**；屏幕上最清晰；**搜索命中率最高**。**投影/打印会变虚** |
      | `tabler-filled` | 1,055 | 圆润实心 | 要**稍强存在感**、但别太硬 |
      | `chunk-filled` | 641 | 粗壮剪影，很重 | 需要**强视觉重量**、图标当视觉锚 |
      | `phosphor-duotone` | 1,518 | 双色调（带 20% 背板） | 要**层次感**；`viewBox` 是 256×256，留意缩放 |

      **三问**：① 要投影/打印吗（要 → 避开 outline）② 视觉重量要轻/中/重 ③ 要不要分层感。
      > `simple-icons`（品牌 logo）**已从本库删除** —— 需要品牌识别时用**文字 + 通用图标**表达。

   2. **再同步图标池** —— 图标在成稿前必须先拷进项目，否则 `finalize` 展开时会报缺失。
      把你打算用的**全部**图标名（`库/名` 形式）一次性传给 `icon_sync.py`：

      ```bash
      python scripts/icon_sync.py . tabler-outline/activity tabler-outline/chart-bar tabler-outline/shield
      ```

      **单库原则**：一行命令里**只能出现一个风格库**（混用会 `exit 1`）。
      **图标名写错**（或该库没有此图标）→ `[MISSING]` 且 `exit 1`。**按提示的 `rg` 命令**在**同一库内**换名重试，
      **不要换库**（`idea`/`goal`/`warning` 这类抽象词搜不到，要翻译成**可绘制的物体**：`bulb`/`target`/`alert-triangle`）。
      实在搜不到 → **让别的载体（图表/排版/形状）承担该语义，不硬塞图标**。

   3. **在正文里写占位** —— 语法 `<use data-icon="库/名" x y width height fill/>`：

      ```xml
      <use data-icon="tabler-outline/activity" x="46" y="204" width="24" height="24" fill="#003C96"/>
      ```

      - `fill` 用该区块对应的等级色（§1.3 一级蓝 / 二级黄 / 三级红），与同区块的色条/标题**同色**。
      - 尺寸 **24~28px** 最稳（卡片小标题旁）；`stroke-width` 仅描边库可覆盖（`tabler-outline` 默认 2）。
      - **只放这四处**：**卡片/区块小标题前**、**流程链节点**、**编号条目行序号位**、**图标网格单元（组件 R5）**。**页面大标题前不放**。
      - **加图标后标题要右移**：图标占用 `x` 空间 → 标题 `x` 与正文 `x` **一起右移**，避免与图标重叠。
        常见写法：图标 `x=46 w=24`（占 46~70）→ 标题/正文从 `x=84` 起（组件 C1 原为 64）。
        **右移后每行可容纳的汉字会少 1 个**（组件 C1 卡从 29 → 28），排版时按新宽度算字数。
3. **保存**：写入 `assets/svg_body/pageXX.svg`（`XX` 与页码一致，如 `page05.svg`）。
   **必须整文件重写**（`Path(p).write_text(svg, encoding='utf-8')`），**别用 `sed` / 正则局部替换** ——
   中文多字节下极易写不进去，且**不报错**（见下方"改片段的两个铁律"）。
   🔴 **别用 `python3 -c "…"` 写含中文的长内联脚本** —— shell 层会吞引号/反引号，实测整段输出报废、
   **白烧 5 分钟**（2026-10-15 平台实跑）。**写文件这类写操作一律不内联**（`python -c` 只留给只读查看），
   先落一个临时 `.py` 再执行。
4. 🔴 **一次调用写完所有片段，别一页一发** —— 实测单页生成成本两法持平（≈`98 秒/页`），
   拆成 N 次调用**不会更快**，只是白付 N−1 轮的思考开销（2026-10-10 实测：分 5 批写净亏 `342s`，
   且**一次中途校验都没做**，照样卡在"全部写完才跑第一次校验"）。
   **最稳的写法 = 一个临时 `.py` 脚本，循环把全部片段一次写盘。**
   > 同一条在「第二步」也有 —— 但那条要**写完才读到**，所以在落笔点再说一遍。

> **落笔前先做一次「宽高自查」（先验，省一轮）** —— 开着校验器写、而不是写完再撞墙：
> 1. **数宽度**：每行文字按所在栏宽对表（契约 §5.0 ②）——三栏 ≤19 字、四栏 ≤14 字（14pt 正文）。
>    **多栏页最容易犯的就是按通栏的语感写长句**（实测 page04/05/07/08 四页全栽在这）。
> 2. **数高度**：写完最后一行的 `y + 0.25×font-size` 是否 ≤ 容器底边；底边统一收在 `648`。
> 3. **扫重叠**：同列相邻两块的净距是否 ≥24px（§2.2）。
> 4. 🔴 **量块内密度**：每块「文字上下跨度 ÷ 容器高」是否 ≥ `50%` ——
>    跨度 = 首行顶（`y − 0.75×字号`）到末行底（`y + 0.25×字号`）；
>    **< 40% 是硬错误**、40~50% 只警告；容器内**无文字**的图块/纯色块跳过；
>    🔴 **整列只有 1 块时豁免**（那种情况下密度与"底边收口"数学互斥，别硬凑）。
>    **"框大内容少"是最隐蔽的一类**：它底边合规、填充率也达标，只有这条能抓。
> 5. 🔴 **量图框纵横比**：每个 `<image>` 的 `宽 ÷ 高 ≤ 2.8`（等价 **图高 ≥ 宽 ÷ 2.8**）——
>    照片一律 `slice` 裁剪，**框越扁，画面越只剩中间一条**；超标就加高，或改 2~3 张横排（每张 `384` 宽）。
>
> **代价对比**：这一步自查约 `10 秒`；不做的话，越界/密度/图框平均要烧 `6~7 分钟` 返工
> （2026-10-10 实测：Step 2 总耗时 `21 分 19 秒`，其中**修越界/密度占 74%**，纯创作只占 28%）。
> ⚠️ **上面这句自己写着"密度占 74%"，可清单原本只有「宽/高/重叠」三项、没有密度** ——
> 2026-10-15 两次平台实跑仍各返工 `4~5 分钟`，栽的正是第 4、5 条与表格重叠
> （块内密度 `39%`、图框 `AR 4.20`）。

#### 第二步：跑创作校验（**全部页面一口气写完 → 一次全量校验**）

> **主节奏 = 一口气全写完 → 跑一次全量校验 → 按报错分别返工**。
>
> 1. **先按"宽高自查"（上一条）把 8 页全部写完** —— 中间**不校验、不停顿、不分批**。
>    🔴 **"分批"含"一页一次工具调用"**：判据是**写盘调用次数**，不是"有没有中途校验"——
>    实测单页生成成本两法持平（≈`98 秒/页`），拆开只会白付轮次开销（见第一步第 4 条）。
> 2. **全部写完后再跑一次校验**（不带参数，扫全部片段），**一次把问题报全**。
> 3. **只对报错的那几页分别返工**，改完再整体复跑一遍确认全绿。
>
> **不要"分批写 + 中途校验"**，也不要"写一页跑一次"——后者更慢：
> 2026-10-10 实测，分 5 批写 **一次中途校验都没做**，SVG 写作从 `364s` 涨到 `706s`（**净亏 342s**），
> 而发现问题的那一刻**和一次写完完全一样**（都是"全部写完才跑第一次校验"）。
> **收益为零、成本巨大** ⇒ 分批写是纯损耗。
>
> **为什么"探针式先跑 1 页"也不成立**（2026-10-10 实测否定）：
> 探针的隐含前提是"第一页犯的错，后面会原样再犯"，**这个前提在本场景不成立** ——
> 8 页通常要用 **4 种以上不同骨架**（契约 §2.1 明文要求反重复），
> 每页的**栏数 / 栏宽 / 容器高**都不一样：`page04`（三栏 384）根本没有 `page13`（通栏 1200 卡）那种"通栏矮卡"结构，
> **一个版式上不可能犯的错，在另一个版式上测不出来** ⇒ **探针没有预测力**。
> **真正防错的是「先验」而不是「探针」**：把栏宽→字数表、容器高→行数在**落笔前**用足（见上一条），
> 这才是把错误挡在写入之前的正道。校验器只管**兜底**。

```bash
cd <SKILL_ROOT>
python scripts/validators/check_creative_svg.py            # 校验全部正文片段
python scripts/validators/check_creative_svg.py page05.svg  # 只校验某一页
```

> **参数只写纯文件名，不要带目录**：脚本内部固定拼 `assets/svg_body/`，传 `assets/svg_body/page05.svg` 会拼成 `assets/svg_body/assets/svg_body/page05.svg` → 报"文件不存在"。工作目录无所谓（脚本按自身位置反推根目录），带不带 `cd` 都能跑。
> 不带参数时扫描 `svg_body/` 下**全部** `.svg`；若此时 `svg_body/` 还不存在，会打印 `[INFO] 无 svg_body/ 目录` 并**正常退出（exit 0）**——这是提示不是报错，说明还没开始创作正文。

校验会拦截：越界盖页头（y<88）、**水平越界（内容越出 `x ∈ [40, 1240]`，契约 §1.4）**、配色/字体/字号违规、照片不存在、**图框过扁（框 AR >2.8，契约 §6.1 硬规则 1）**、**底部严重留白（内容底边 <560，契约 §2.4 指标④）**、**纵向跨度不足（内容底边−顶边 <464 —— 即"整体下移"，契约 §5.0.1 铁律）**、canonical 规则、残留占位符等**硬错误**；填充率 <25%、**裁剪偏重（对原图真实保留率 <55%）**、分栏失衡、**底部留白偏大（底边 560~608）**、**跨度擦线（464~504）**、**块内密度 40~50%** 只**警告**不阻断。

> **「块内密度」在「该列纵向块数 = 1」时一律降为软警告** —— 单块列收口必须撑满整列 `544`（密度必然低）、
> 缩到相称则跨度必 <504（**两条判据数学互斥**）；真问题（素材量不足）由 Step 1f 的**内容量下限**提前拦下。
> **识别信号**：报错在「密度」与「跨度」之间来回换 ⇒ **别再微调，直接换骨架**（§5.0.1 第 3 步）。完整推导见 `pitfalls.md`。
>
> **骨架规划的前验（2026-10-13 补）—— 素材量偏低时别用「多栏 + 高容器」**：
> 密度 = 文字跨度 ÷ 框高，**块数 ≥ 2 时低于 40% 是硬错**（只有单块才豁免）。
> 素材达成率低（如 < 80%）意味着每块能填的字本来就少，此时**一栏一行的大框必踩线**
> ⇒ **优先「单容器通栏」或「少栏 + 矮容器」**，把有限的字集中起来。
> **实测反例**：一份达成率 63% 的片子，`3 卡片` 页密度 39%、`流程链` 页 24% → 30% 连续两轮硬错，
> 最后改成 §5.3-A 单容器才通过 —— **白烧 3 轮**。
> **反过来用**：**规划骨架前先看素材量**（§0b ② 的达成率、每块大概能填多少字），再定栏数与容器高。
>
> **两条口径**：① `纵向跨度不足` / `水平越界` 均为**硬错误**（擦线档为软警告）—— 前者抓"整体下移"、后者抓"冲出右边界"（原先只查 y、不查 x）。
> ② **块内密度阻断线"前紧后松"**：Step 1f `<45%` 阻断、本步 `<40%` 阻断（蓝图阶段改数字成本极低、适合卡严；SVG 阶段改布局可能多轮重写、只在明显半空时兜底）。

> 裁剪检查会 `PIL` 读原图尺寸算**真实保留率**——所以"框 AR 没超标 ≠ 没裁狠"：
> 框 `580×214` 的 AR 只有 2.71（合规），但放进一张 4:3 实拍图实际只保留 49%，会给出 提示。

**不通过（脚本 exit 1，即有硬错误）→ 照报错改片段 → 再校验，迭代到硬错误清零为止。**
**不允许带着未通过校验的正文进入 Step 3。**

> **返工时务必"横向扫一遍同类版式"**：同一类错误（图框压扁 / 字号写错 / 组件用错 / 多栏写长）在某页出现后，
> **顺手检查其余骨架相同或栏宽相同的页面有没有同样问题**，一次改干净，别等下一轮校验又冒出来。
> **但别扩大成"全篇通读"**：只扫**同骨架**的页（栏数/栏宽/容器高一致）——
> 不同骨架之间没有传染性（见上方"探针不成立"的论证），逐页通读是白费工。

#### 🔴 返工第一原则：**先挪位，不许直接删**

> **为什么单列这一条（2026-10-18 平台实测）**：那次报错是
> 「`G1 键值参数行` at `y=592` overlaps with the left cards（`y=390, h=258` → 底边 648）」，
> 模型的修正动作是「**移除重叠的 G1/G3**」——把**已经写好的非 C 族组件**删掉，换成 C 族填空间。
> 结果：**非 C 族掉回 0 处**，一整个下午想推的 R/G/L 覆盖全部落空。
>
> **机理**：C1/C2 这类是**主结构**，永远不会被报"多余"；`G1~G5 / C3 / C4 / C6 / C8` 是**附加物**，
> 一旦撞上主结构，删掉是**最省事**的解法。⇒ **判据越严，配件越少**，与"多用非 C 族"方向正好相反。

**报错是"配件与主结构重叠"时，按下面四步依次试，前三步都不行才允许删：**

| 步 | 做法 | 具体坐标 |
|---|---|---|
| 1 | **下压**到主结构之外 | 配件顶边 = `主结构底边 + 24`；整条下移后**底边仍须 ≤ 648** |
| 2 | **嵌进宿主卡内底边** | 距卡底 `≥16`（如卡底 648 ⇒ 配件基线 `632`），左边与卡内文字同缩进（`x+12` 或 `x+24`）|
| 3 | **缩到最小高度** | `G1` 行高可压到 `22`（标签 + 值同行）、`G3` 可压到 `18`；**不许改字号**（正文 `18.67` 铁律）|
| 4 | 确实放不下 ⇒ **删，并在收尾说明"删了哪个、为什么"** | 只删**这一条**，**不许连带动别的配件** |

> 🔴 **禁止的返工动作**：
> - ❌ 把 `G1/G2/G4/G5` 整组删掉换取"校验全绿" —— 那等于**用非 C 族换通过率**；
> - ❌ 删掉配件后**不补位**、让它原来的位置空着（空间会立刻被密度判据抓）；
> - ❌ 改为"把配件塞进卡内已有文字的同一个 `y`" —— 那是**文字压文字**，比重叠更糟。
>
> **对齐判据**：配件行的 `y` 一定落在**主结构底边之外**，或**宿主卡内底边 16~40px 的区间**；
> 落在这两条带里就不会与主结构重叠，也不必删。

> **改片段的两个铁律（2026-10-10 实测：违反任一条都要白烧 1~3 轮）**：
>
> **① 一次改到位，别挤牙膏。** 同一页的同类问题（一行超宽、下一行也超宽）**必须一次全改**。
> 实测 page07 因**分三次**各删 1~2 个字，白烧 `64s + 75s + 26s = 165s`（占全步返工时间的 12%）。
> ⇒ **拿到报错后先扫全页**：把该页所有"文字越界"行一次列全、一次性改完，再回校验。
>
> **② 改完立刻回读确认，别假设写进去了。** 实测出现过**改了文件但校验器仍报旧内容** ——
> 重写方式不对（用了 `sed`/正则替换处理多字节中文、或写到别处）⇒ 文件其实没变，
> 白白多花 `12s + 75s` 才发现。**正解**：
> - **用整文件重写**（Python `Path(p).write_text(svg, encoding='utf-8')`），**不要**用 `sed` / 正则做局部替换；
> - 写完**立刻回读一次**校验器报的那一行（或直接重跑 `check_creative_svg.py <page>.svg`），确认旧文本确实没了；
> - **判据**：若"改了却没变化" ⇒ **先怀疑写入没生效，别怀疑判据**（判据不会自己变）。

> **警告（）不算"不通过"** —— 只有**硬错误（，脚本 exit 1）必须当场改**。
> 警告的处理原则：**一次能改好就改；改不了一次就放过，继续下一页** ——
> **绝不要为一个警告反复改写同一页。**
> （实测教训：曾为「净字数 133 < 140」这种**不阻断的警告**改了两轮、内容几乎没变，白费数分钟。）
> 警告留到**全部写完后的最终全量校验**再看一眼 —— 那时统一判断哪些值得改、哪些放过。

> **改完后再跑一次不带参数的全量校验作最终确认**（`check_creative_svg.py`）——
> 确保整批齐备、没有中途漏写的页面。

#### 第三步：在 JSON 里登记该页

```json
{
  "id": "page04",
  "page": 4,
  "template": "009_content.svg",
  "output": "slide_04_progress_cards.svg",
  "text": { "PAGE_TITLE": "页面标题" },
  "body_svg": "page04.svg"
}
```

- `text` **只放 `PAGE_TITLE`**——**取自 design_spec.md 该页蓝图开头的占位符表格行**（`| `PAGE_TITLE` | 内容 | `≤N字` |`；N = **当前风格** `pipeline_config.schema.json` 里 `009_content.PAGE_TITLE.max_chars`，已在 Step 1f 校验），正文不进 text。若蓝图缺那张占位符表，说明 Step 1 有漏项，先回 §IX 补上。
- `body_svg`：指向刚写好的正文片段文件名（在 `assets/svg_body/` 下）。
- 照片直接写在正文片段里（&lt;image href="../sources/image_NNN.jpeg"&gt;），不需要 `photos` 字段。

### Step 2d：JSON 标点安全检查（每页当场做）

**每写完一个 page 对象，立即检查以下规则**：

| 禁止 | 替代方案 |
|---------|------------|
| 中文引号 `""` | 使用 `「」`（直角引号），或英文引号 `""` 需写 `\"` |
| 字符串值内部未转义的 `"` | 加 `\` 转义，或改用 `「」` |
| 尾随逗号 | 最后一个元素后不能有逗号（数组末尾、对象末尾） |
| 单引号 `'` | JSON 只用双引号 `"` |
| `&` 未处理 | 直接写 `&` 即可，`build_svgs.py` 的 `xml_escape()` 会自动转义为 `&amp;` |

**中文引号是最常见的问题源**。从 §IX 复制内容到 JSON 时，如果原文用了 `""`，统一替换为 `「」`。

### Step 2e：配置全量校验（字数 + JSON 完整性 + 槽位）

**全部 page 写完后，一条命令跑完三项校验**（一轮完成，不必分三次调用）：

```bash
cd <SKILL_ROOT>
python scripts/validators/check_step2_config.py
```

内部**依次执行三项，且全部执行、不因前一项失败而跳过后续** —— 一次把问题报全，避免"修好一个又冒一个"的多轮返工。任一项失败 → 整体 `exit 1`。

| # | 检查项 | 底层脚本 | 查什么 |
|---|--------|---------|--------|
| ① | 设计稿复核（字数 + 骨架分布 + **布局框坐标**） | `check_design_spec.py` | `design_spec.md` §IX 各占位符是否超 `max_chars`；版式骨架反重复；**布局框**四项（底边 ≤648 / 同列间距 ≥24 / 左右等高 / **最下框底边 ≥608**）。本步属**复跑**，design_spec 已定稿，通常与 1f 结论一致 |
| ② | JSON 完整性 | `check_json_integrity.py` | 语法 / 顶层结构 / 字段 / template / body_svg / 页序结构 |
| ③ | 槽位完整性 | `check_required_slots.py` | 各页模板要求的占位符是否填全（清单取自 `placeholder_schema`） |

> **单项排错**时可只跑其中一个，例如 `python scripts/validators/check_json_integrity.py`。

#### ① 字数二次校验

- **门面页**：每个占位符的**折算字**是否 ≤ `max_chars`（口径 = **中文 1 ／ 标点·字母·数字 0.5**，空格不计 —— 与 Step 1 §1e 同一口径）；模板要求的占位符是否全部出现。
- **009 创作页**：蓝图里的「字数预算」是否满足**填充率 ≥25%**（创作区 1200×632）。填充率的机器校验在 `check_creative_svg.py` 里已做，这里只需确认蓝图预算合理。
- **如果发现超限**：回到 §IX 压缩内容，然后同步更新 JSON（和/或正文 SVG 片段）。不允许"先在 JSON 里改短、§IX 留旧的"——两者必须一致。

#### ② JSON 完整性 —— 六项

| # | 检查项 | 不合格时怎么修 |
|---|---|---|
| ① | JSON 语法 | 检查中文引号 → `「」`、字符串值内未转义的 `"`、尾随逗号、单引号 |
| ② | **顶层结构**：`pages` 必须存在且非空 | 顶层键名写错（如误写成 `slides`）或整个数组漏写；正确结构 `{"_meta": {...}, "pages": [...]}` |
| ③ | 字段完整性：每页含 `id`/`template`/`output`/`text` | 补上对应 page 漏写的字段 |
| ④ | `template` 值合法（规范化后须存在于 `templates/`） | 按报错里列出的「可用模板」改正。**009 创作页的模板名是 `009_content.svg`**（design_spec.md 里称 `009_creative`，但写进配置必须用 `009_content.svg`） |
| ⑤ | **009 页的 `body_svg`**：字段存在 + 片段文件存在于 `svg_body/` | 补 `body_svg` 字段；片段要放在 `assets/svg_body/` 下、文件名与字段值一致（如 `page04.svg`） |
| ⑥ | **页序结构**：封面第一 / 致谢最后 / 目录紧跟封面 / 每个章节过渡页之后必须有该章内容页 | 常见是**内容页全连排、章节过渡页被堆到末尾**。按「封面 → 目录 → 【第1章：过渡页 + 内容页×N】→ … → 致谢」重排 `pages[]` 顺序（只调顺序，不改内容） |

> **② 是防「假通过」的闸门，别小看它**：`pages` 缺失或为空时，③④⑤ 的逐页检查会**全部空转、统统打印 **，
> 配置错误被一路放行到 Step 3 build 才崩 —— 而且是**串行暴露**（先 `KeyError: 'pages'`，改完再崩 `template`，
> 再改又崩 `body_svg`），在自动化平台上就会表现为"反复失败、反复自动修复"。有了②，这三类错**一次全报出**。

#### ③ 槽位完整性

**这是防止"页面有空槽"的最后一道防线** —— 逐页检查 `text` 对象是否包含该模板的**全部**占位符：

- **门面页**：清单**直接取自** `schema.json` 的 `_template_reference.<模板>.placeholder_schema`（脚本自己读，你不必翻）。
- **009 页**：只有一个 `PAGE_TITLE`。

如果报 `❌`，回到 design_spec.md §IX 补全该页缺失的占位符内容，然后同步更新 JSON。**不允许带着空槽进入 build。**

> **校验范围 = 模板里的全部占位符**（与 `build_svgs.py` 替换时用的是同一份定义）——
> 2026-09-29 起不再读另一份手工清单 `required_slots`：它与 `placeholder_schema` 描述同一件事、属两次手工录入，必然漂移。
> 实测 `002_toc` 模板有 12 个占位符而那份清单只列了 4 个（`_NUM` / `_EN` 全漏）、`002_toc_3ch` 漏 6 个、`003_toc` 漏 2 个 —— 漏填时校验抓不到，`{{...}}` 会一路印到成品。

**三项全 才能继续。**

> **顺带自检 `_meta` 两个字段**（机器不查，靠你核一眼）：
> - **`palette`** = 前置解析到的配色 id（缺省 `default`），且确为 `assets/palettes/<值>.json` 现有方案（`ls assets/palettes/*.json`；`roles.json` 是角色表）。
> **它只管创作页（009）** —— 别指望改它能变封面/目录风格。写无效值 ⇒ Step 3 回退 `default` + 告警（**不中断**），但成品配色与调用方预期不符 ⇒ **在前置就改对**。
> - **`template_set`** 一般**省略**（脚本从 `palette` 派生同名风格目录，不存在则回退 `default`）。只在**显式写**时才需确认目录存在（写错 ⇒ build **报错退出**，不静默降级）。**现有风格目录有 `default` / `minimal` / `vibrant` 三个**（`ls assets/templates/*/`），省略它即可正常派生，不需要手写。
> 取值规则与原子回退机制见 §2b，此处不重复。

### Step 2f：来源标注自动注入（图片行 + 文字行）

**只在有外部来源时才产生改动** —— 两类各自判断；都无命中时脚本幂等、不产生任何改动。
无论有没有网图 / 网文，**本步都照常执行**。

**你在 Step 2 唯一要做的事**：写正文片段时，若这一页用了某几条**网文事实**，
就在片段里留一行锚点 `<!--FACTS: F001,F003-->`（契约 §1.6）。
**两种来源标注行本身都不用你写** —— 脚本按下面两条判定自动插入。

> **只能从 `_web_text_facts.json` 里「选」id，不能「造」** —— 若发现源文里有**未登记**的事实，
> **停下、回 §0d 补登记**（补 `文本.md` 要点 + `facts.json` 一条），再复跑 `check_web_research.py`；
> 若新增内容影响到页面规划，还要复核 Step 1 的 `design_spec.md`。（见 `step_0_extract.md` §0d「回流规则」）
> **也不要在 Step 2 直接改 `文本.md`** —— 它的**正文**在 §0e 通过后**即冻结**
> （唯一例外：§0f 往末尾「## 联网补充图片」段追加图片登记行）；Step 1 的设计稿以**正文**为依据，中途改会让两边漂移。

```bash
cd <SKILL_ROOT>
python scripts/inject_image_credits.py
```

**它做什么**（两类，锚点不同）：

| 行 | 判定 | 锚点 |
|---|---|---|
| **图片来源行** | 读 `文本.md` 的「网图」编号 → 扫 `svg_body/*.svg` 的**实际 `href` 引用** → **求交集** | `image_NNN`（硬锚点，机器可查） |
| **内容来源行** | 扫片段里的 **`<!--FACTS: …-->`** → 到 `_web_text_facts.json` 查站点 | `fact_id`（**模型显式声明**） |

非空则该页插入标注；为空则**移除**已有标注。

**为什么必须有锚点**：Step 1（`design_spec.md §VIII`）标了实拍 / 网图，但**「标了」不等于「用了」**；
文字更是**没有天然编号** —— 所以只能靠 `<!--FACTS: …-->` 这个显式声明。
`check_web_research.py` 会校验声明里的每个 id **都真实存在**（契约 §1.6：**不能漏、不能编**）。

**上下顺序**（契约 §1.6）：只有一类 → 该行 `y=690`；两类都有 → 图片 `y=668`（上）／ 文字 `y=690`（下）。

**幂等**：两个标注块分别夹在 `<!--IMG_CREDIT_BEGIN-->`/`<!--IMG_CREDIT_END-->` 与
`<!--TEXT_CREDIT_BEGIN-->`/`<!--TEXT_CREDIT_END-->` 之间，重跑先删后插 ——
换素材、改配置、重跑若干次都不会留残迹或重复。
**`<!--FACTS: …-->` 锚点不会被删**（它是内容凭据，不是标注）。

**预期输出**：

```
=== 来源标注注入（Step 2f：图片来源行 + 内容来源行）===
文本.md 网图: 1 张
    image_015.jpg  ← www.example.com
网文事实: 2 条
    F001  ← zh.wikipedia.org
    F002  ← www.gov.cn

  ✅ page04.svg
       图片行 ← 引用网图: image_015.jpg
       文字行 ← 事实锚点: F001
  ·  page07.svg  无外部引用，跳过
  🧹 page09.svg  无外部引用 → 已清除旧标注

✅ 注入 1 个、清除 1 个
```

**参数**：`--dry-run`（只报告不落盘）、`--page page04.svg`（只处理某页）。

**注入的标注长什么样**（规格见契约 §1.6，**不要手写、也不要去改它**）——
两类都有时（图片在上、文字在下）：

```xml
<!--IMG_CREDIT_BEGIN-->
<text x="40" y="668" font-size="18.67" fill="#808080" data-role="img-credit">图片来源：网络 · 仅作示意（www.example.com）</text>
<!--IMG_CREDIT_END-->
<!--TEXT_CREDIT_BEGIN-->
<text x="40" y="690" font-size="18.67" fill="#808080" data-role="text-credit">内容来源：网络 · 仅供参考（zh.wikipedia.org）</text>
<!--TEXT_CREDIT_END-->
```

> **不要手动编辑标注块** —— 它是机械产物，你改了下次重跑会被覆盖。
> **不要在 `y>648` 放别的东西** —— 那里只有来源标注能占（契约 §1.6）。
> 若报「有网图但没被任何页引用」→ 说明素材备了网图却没用上，PPT 里不会出现网图。
> 这通常意味着 Step 1 配图分配有遗漏（图备了就该用），回 `design_spec.md §VIII` 补分配即可。

#### 取值速查（示例中每个具体值的来源与缺省）

**上例里的值一律不得照抄**。逐字段来源如下 —— **取不到就按「缺省」列填，绝不编造**：

| 字段 | 来源 | 素材里取不到时 |
|---|---|---|
| `_meta.project` | design_spec.md §I `Project Name`（= 封面 `TITLE`，**同源**） | 有现成主标题 → 用原题；**无 → 据内容拟题**（`step_1` §1e）；仍定不出 → `未命名项目`。冒号须**全角**（半角 `:` 会使导出失败） |
| `_meta.author` | **只能来自素材**，优先级见 §2b（文件名 → 正文署名 → 兜底） | `TCC` |
| `_meta.palette` | **前置解析的 `[PPT风格：xxx]`**（配色方案 id，**只管 009**） | `default` |
| `_meta.template_set` | **一般省略**（方案 C：由脚本从 `palette` **自动派生**同名风格；不存在则回退 `default`）。只在「门面页风格 ≠ 配色 id」的混搭场景才显式写 | **省略**（= 派生 | 回退 `default`） |
| `TITLE` | 封面主标题（与 `_meta.project` 同源；**无现成标题时主动拟题**，见 `step_1` §1e） | 同 `_meta.project` |
| `TITLE_EN` | **`TITLE` 的忠实英文翻译**（不是自由创作，不得增删语义） | 素材为纯中文且无法翻译 → 保留 `TITLE` 原样 |
| `AUTHOR` | 同 `_meta.author`（**两处必须一致**，≤5字） | `TCC` |
| `DATE` | **当前系统日期**（实际取一次，勿手写；见 `step_1` §1e） | — 必填 |
| `PAGE_TITLE` | design_spec.md 该页蓝图开头的占位符表格行（§2c-2） | — 蓝图必填，缺则回 Step 1 补 |
| `TOC_ITEM_x_TITLE` / `_NUM` | 各章标题（来自素材的板块划分） | — 章节必来自素材 |
| `TOC_ITEM_x_EN` | 对应 `_TITLE` 的**忠实英文翻译** | 无法翻译 → 保留中文 |
| `CHAPTER_TITLE` / `_DESC_LINE1/2` | 各过渡页的章标题与描述（来自素材） | — 章节必来自素材 |
| `output`（文件名 slug） | 从**该页真实主题**提炼的英文短词 | — 见 §2b 第 4 条 |
| `body_svg` | 该页正文片段在 `assets/svg_body/` 下的文件名 | — 与 `id` 对应 |

> **`TITLE_EN` / `TOC_ITEM_x_EN` 是必填槽位，但素材里没有英文** —— 所以它们**必须由你依据对应中文翻译而来**。
> **硬禁止**：不许在翻译时**增添中文里没有的语义**（例：中文「项目认知」→ 英文只能是 `Project Overview`，
> **不能**写成 `Project Overview & EPC` —— `& EPC` 中文里没有，属于**加料**）。

> - **page01（门面页）**：`text` 按 `_template_reference.001_cover.placeholder_schema` 逐项填，无 `body_svg`。
> - **page04（009 创作页）**：`text` 只有 `PAGE_TITLE`，正文在 `assets/svg_body/page04.svg`（须先通过 `check_creative_svg.py`）。
> - **page05（致谢页）**：无文本占位符，`text` 写空对象 `{}`。
